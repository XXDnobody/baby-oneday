# A版新增页面设计

依据用户“根据刚才新提的需求设计下页面”和最新v0.2需求。沿用A的窄侧栏、松绿、近白表面、18px面板、清晰中文字级；本轮为已确认方向的扩展。

| 页面 | 信息角色、距离和容量 | 布局来自内容的哪里 |
| --- | --- | --- |
| AI助手 | 父母在电脑50–80cm或手机近读；对话与最终方案同时可核对 | 电脑对话和改动对照并排，页面内可打开侧面板；手机讨论/方案两页签 |
| 统一日历 | 一个月选日期，一天看具体事；日期格仅放标记 | 电脑月历与选中日并排；手机紧凑月历在上、日详情在下 |
| 记一下 | 短操作；日期关联清楚，四类内容选填 | 发生时间、关联安排、参与与反应、家长原话、照片；底部一次保存 |
| 记录详情 | 过去发生的事近读；少量照片与完整原话 | 记录内容先看，当时安排可展开；活动实例与发生日固定关联 |

设计温度保持安静、清楚。正式计划使用松绿，待确认方案使用浅暖提示，实际记录使用文字标签与图标，状态不只依赖颜色。导航采用今天、日历、饮食、活动、家庭；固定AI入口进入同一会话。

## 可体验的主要流程

1. 今日打开AI → 讨论今天/本周 → 对照原安排与建议 → 继续说“只改晚餐”或“周三保持原样” → 新版本替换旧预览 → 一次确认，整组写入本机原型 → 日历、菜单和大屏读取保存结果。
2. 日历选未来看已保存安排；选今天调整或记一下；选过去先看记录，再展开当时计划。未确认AI草稿不进入日历。
3. 活动“记一下”带入这次安排；参与情况、兴趣、感想、照片至少有一项即可保存。可以补记独立事件，填写时间与发生时间分开显示。
4. 相同活动的多次记录彼此独立。替换活动后，原记录仍保留当时的活动标题、时间与内容版本。
5. 照片逐张预览和移除；失败示例可以先保存文字，再重试照片，不重复新增记录。

## 原型边界与示例

AI为可交互演示，不调用模型。照片保存在本机原型，处理和失败状态用于评审，不模拟已连接云存储。原型暂设3张/次、每张5MB作为演示限制，正式上传规则尚待选型。

历史记录中的文字均标为示例；照片复用此前生成的积木场景，明确不是家庭真实照片。城市、真实家庭经历和宝宝表现不作推断。原A版文件保留在 `versions/a-v1/`。

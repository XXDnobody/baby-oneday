# 宝宝计划｜开发规格

版本：v0.6，更新于 2026-10-30（Asia/Shanghai）。状态：与产品需求 v1.0 对齐，业务及验收纳入 [S1-2026-10-30 冻结基线](../specs/baby-plan/baseline.md)，保留 D-11 自家计划与文字记录及 30 天恢复决定；工程方案仍待细化和实现验证，待定项见[需求对齐与待定事项](需求对齐与待定事项.md)。微信接入不作为首版前置条件。

本文件将[产品需求](产品需求.md)、[页面结构](页面结构.md)和[技术方案](技术方案.md)落到实施范围、权限、页面与验收。接口及数据结构见[接口与数据模型](接口与数据模型.md)。文档完成不表示服务已开发或已部署。

## 1. 已确认规则

| 编号 | 当前结论与状态 | 对实现的要求 |
| --- | --- | --- |
| D-01 | 首版邮箱＋密码，首次验证邮箱，常用设备保持登录；忘记密码时邮件重置 | 每人独立账号；补齐邮箱验证、邮件重置和可撤销设备会话；微信不作为首版前置条件 |
| D-02 | 奶奶也能换餐、调整活动与时间 | 爸爸为家庭管理员；妈妈与奶奶均为日常编辑成员，设备不决定权限 |
| D-03 | AI 聊天和草稿仅本人可见，确认后的计划共享 | 会话、消息、方案以发起人为访问边界；共享计划不包含聊天原文 |
| D-04 | 每天晚上准备明天，一周计划按需生成 | 初次使用生成今天；夜间准备次日；一周方案通过 AI 讨论与确认保存 |
| D-05 | 已取代：家庭照片上传和留存退出当前范围 | 取消原图、缩略图、附件、容量与照片备份要求；内容说明配图保留 |
| D-06 | 记录仅本人和家庭管理员可更正或删除 | 编辑日常计划不赋予修改他人记录的权限；更正保留作者和修改历史 |
| D-07 | 妈妈和奶奶可改食材、近期偏好、作息模板；宝宝关键资料、禁忌及自动生成设置由管理员修改 | 权限落实到对应字段、接口和 AI 操作，不只控制页面按钮 |
| D-08 | 内容启用范围仅家庭管理员可修改 | 妈妈、奶奶可在已启用内容中换餐、调整活动；不改变既有日常编辑权限 |
| D-09 | 活动卡以图文为主，英语音频按核心需要补充，视频后置 | 内容说明配图与已取消的家庭照片上传分开；音频尚不作为必须交付项 |
| D-10 | 核查后已确认首批复用范围 | 目标为 4 位成员、全家共用的“五一”家庭，排除同名其他档案；2026-10-30 用户确认必要基本资料＋全部 [11 条菜谱草稿](首批资料复用清单.md)，历史计划和流水后置。技术合并规则已核清，内容补齐后由管理员选择启用；尚未执行迁移 |
| D-11 | 自家使用期间保留计划和文字记录，删除后 30 天内可恢复 | 不按记录年龄自动清理；容量问题显式处理。回收站涵盖计划条目与文字／反馈记录，恢复沿用当前权限；备份保存期与恢复成本另行核实，不自动扩展为对外会员政策 |

此前已确认：A 日常工作台；手机、电脑、平板共用 Web；平板直接操作；AI 写入先预览再一次确认；局部修改保留其他安排；日历统一计划和回顾；先自家使用，再邀请 10～20 个家庭试用 7 天，再测试家庭会员。

下文“工程建议”可在实现与实测中调整；“待确认”涉及尚未确定的产品行为，不以默认选项或时间经过视为用户同意。

## 2. 分阶段交付范围

| 阶段 | 必须交付 | 进入下一阶段的依据 |
| --- | --- | --- |
| S1 自家可用 | 账号及家庭邀请、初始化、模板、共享计划、食材与菜谱、活动及来源、天气穿搭、AI、日历、文字与反馈记录、回收站、平板、打印；数据库备份恢复 | 真实设备上完成一周使用，覆盖工作日和周末；核心保存、权限、同步及删除恢复验证通过 |
| S2 外部试用 | 新家庭初始化、7 天试用码、家庭权益与用量、到期查看与导出、明确的内容年龄范围及保存政策、基本运营管理 | 10～20 个受邀家庭能够独立开始使用；试用与到期行为通过验证，有实际用量和反馈 |
| S3 收费测试 | 单一套餐、订单核实、会员激活码、续费、退款和权益处理 | 订单、兑换、并发续费及退款验证通过，价格和额度有成本依据 |
| S4 公开推广 | 产品介绍、分享预览与可撤销快照、购买成功直接开通 | 私有数据与公开内容隔离，支付通知幂等，容量经实测 |

S1 的交付包含 AI、天气和文字反馈记录；先做手动共享计划只是实施顺序中的首个可运行版本。家庭隔离和多成员权限从 S1 建立。试用码、会员码、家庭邀请仍是三个独立概念。

本规格继续以一名宝宝的首版界面为范围，数据关联保留宝宝标识。自动照片分析、自动成长评估、完整睡眠/进食打卡沿用原需求中的后续评估状态。衣橱照片入库和逐件搭配已按 2026-10-31 用户新要求纳入当前开发，验收及工程边界见 [CR 衣物搭配](../specs/baby-plan/wardrobe.md)。

## 3. 技术实施基线（工程建议）

| 层次 | 选择 | 边界 |
| --- | --- | --- |
| 界面 | React + Next.js + TypeScript，沿用 A 版视觉和交互 | 响应式 Web；按页面拆组件，复用样式规范与可验证交互 |
| 业务接口 | Next.js Route Handlers + 独立业务服务模块 | 授权、校验和事务在服务端；Web 与任务进程复用同一业务规则 |
| 定时与耗时任务 | 同一代码库中的独立 Node.js 任务进程，任务状态持久化 | 次日计划、导出、记录清理与重试 |
| 数据 | PostgreSQL，版本化数据库迁移 | 正式计划、历史记录、事务、约束及查询索引；访问库与具体版本在兼容性验证后锁定 |
| 内容素材 | 菜谱与活动说明配图按静态素材发布，具体方式由工程落实 | 不建设家庭照片上传、私有相册或原图对象存储 |
| 多端同步 | HTTPS 修改 + SSE 更新通知，断开时重新取数 | SSE 不承载完整家庭内容；通知不能替代读取接口的鉴权 |
| 部署 | Docker Compose + Nginx + 独立持久卷 | 应用、任务进程和数据库分别运行；密钥和生产数据不放入源码 |

具体依赖版本在项目初始化时锁定并验证，不能将本表视为已经完成兼容性测试。Next.js 支持[自定义服务端接口](https://nextjs.org/docs/app/api-reference/file-conventions/route)及[自托管](https://nextjs.org/docs/app/guides/self-hosting)；Compose 可管理多容器服务、网络和卷，见[官方文档](https://docs.docker.com/compose/)。上述组合是本项目的工程选择。

## 4. 成员与内容权限

| 操作 | 家庭管理员（爸爸） | 日常编辑成员（妈妈、奶奶） |
| --- | --- | --- |
| 查看本家庭计划、食材、活动、记录 | 可以 | 可以 |
| 换餐、调整活动与时间、确认自己的 AI 方案 | 可以 | 可以 |
| 新增记录 | 可以 | 可以 |
| 更正或删除自己的记录 | 可以 | 可以 |
| 更正或删除其他家人的记录 | 可以，保留作者与更正者 | 不可以 |
| 恢复回收站中的计划条目 | 可以 | 可以，沿用日常计划编辑权限 |
| 查看或恢复回收站中的文字记录 | 可以 | 仅本人的记录 |
| 查看其他家人的 AI 聊天和未确认方案 | 不可以 | 不可以 |
| 邀请、移除家人，调整成员角色 | 可以 | 不可以 |
| 修改食材、近期偏好、作息模板 | 可以 | 可以 |
| 修改宝宝关键资料、禁忌和自动生成设置 | 可以 | 仅查看，管理员修改 |
| 选择家庭共同提醒 | 可以 | 查看；沿用管理员选定的已认可提醒 |
| 修改内容启用范围 | 可以 | 仅查看，可在已启用内容中调整当天安排 |

日常资料与关键资料权限已由 D-07 确认，内容启用范围仅管理员可改已由 D-08 确认。管理员管理成员关系，不因此获得成员账号密码或私有聊天访问权。撤销成员关系时，停止其对此家庭的接口和同步访问，不删除其原有记录。

建议记录修订界面显示“原记录人、最后修改人、修改时间”，管理员更正他人记录时填写简短原因。共享记录历史沿用同一记录的读取权限；被删除内容不再通过普通详情或历史接口读取。回收站另行检查当前成员资格与原对象恢复权限，不因知道标识而扩大访问范围；最后一位管理员不能被移除或降级。

## 5. 账号、邀请和初次设置

- 首版使用邮箱＋密码登录，首次验证邮箱，忘记密码时通过邮件重置。邮箱是登录标识，家庭内仍显示称呼；显示称呼可重复。每位成员使用自己能收信的邮箱建立独立账号。
- 自家阶段采用受邀注册；首位管理员通过受控的初始化流程创建，其他家人接受邀请后使用自己的账号。已有账号接受邀请时不再创建账号。
- 家庭邀请展示目标家庭与将授予的角色；接受、撤销、过期有明确结果；单次使用及并发消费由服务端保证。
- “保持登录”使用服务端可撤销会话，支持查看并退出自己的其他设备。修改密码、账号恢复后撤销旧会话。具体会话期限是工程参数，需在登录流程实现前记录。
- 密码重置邮件发往账号已验证邮箱。成功重置后撤销旧会话及未使用的旧重置凭证，返回登录页使用新密码登录。家庭管理员不能通过普通成员管理接口接管其他成员账号。邮箱本身无法访问时，不自动按家庭角色重置或更换；人工恢复边界在对外试用前另行确定。
- 创建家庭依次填写：宝宝称呼及月龄依据、城市和时区、禁忌及确认状态、工作日/周末模板、内容启用范围。确切生日为可选；只提供月龄时保存月龄与确认日期，不编造生日。
- 初次设置允许保存进度；未完成关键禁忌确认时可以看模板，餐食只显示待确认候选。完成后进入今日页，再邀请家人和核对食材。

### 5.1 邮箱登录与找回流程

| 场景 | 首版行为 |
| --- | --- |
| 首次注册 | 通过有效家庭邀请或受控初始化入口验证邮箱，再设置密码及本人显示称呼；完成验证与注册前不开放家庭资料 |
| 日常登录 | 邮箱＋密码；可选择保持登录，不要求每次收验证码；未登录用户的错误提示不区分邮箱不存在与密码错误 |
| 常用平板 | 使用实际使用者的账号保持登录，后续直接进入；退出、会话过期、改密码或账号恢复后重新登录 |
| 忘记密码 | 填邮箱→收重置邮件→打开链接设置新密码→返回登录页；重置链接有期限且只能成功使用一次 |
| 收不到邮件 | 展示检查邮箱地址和垃圾箱的提示，提供有冷却时间的重发入口；不显示“已收件”或跳过邮箱验证 |
| 凭证失效 | 验证码或重置链接过期、已使用时说明失效并引导重新申请，不改动现有账号或家庭资料 |

工程建议：注册使用邮件验证码，便于手机收信后在平板输入；重置使用一次性链接。验证邮箱后才设置密码，避免未验证请求预先替他人设置凭证。验证成功也不替代家庭邀请，最终注册时再次检查邀请是否有效并一次消费。

初始工程参数建议：邮箱验证码及重置链接有效 10 分钟，发信重试间隔至少 60 秒；验证码最多尝试 5 次后需重新申请。保持登录建议闲置 30 天失效、每次登录最长 90 天；未选择保持登录最长 12 小时。参数须在实现时集中配置并验证，属于工程建议，不表示永久登录或已经实测。

邮件发信由后端接入事务邮件服务；需要确定发信域名、DNS 验证、发件地址与服务额度，并实测家人使用的邮箱。供应商尚未选定；例如腾讯云邮件推送要求配置并验证发信域名及相应 DNS 记录，见[官方邮件配置说明](https://cloud.tencent.cn/document/product/1288/47454)。开发环境使用测试收件箱，实际发送前另行核对收件人与用途。

重置请求统一回应；凭证安全生成、限次、限时、单次消费，重置后撤销旧会话。实现依据见[OWASP 密码重置指南](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。接口和字段见[接口与数据模型](接口与数据模型.md)。

微信登录暂不纳入首版，也无需继续核对后台来推进当前开发。已有资源证据保留在[微信登录接入核查](微信登录接入核查.md)；以后决定接入时，再核实权限并设计绑定现有内部账号的流程。

## 6. 每日计划与局部调整

1. 初次设置完成，按家庭启用的模板和已核对内容准备今天的安排；无适合条目时明确保留待安排状态。
2. 每晚准备次日。建议默认家庭当地时间 20:00，可由管理员调整；20:00 是可讨论的初始参数，用户确认的是“每天晚上”。
3. 已存在的人工安排和已确认 AI 选择受到保护；自动任务只补尚未形成正式选择的条目。过去日期不由后台补写成“当时已安排”。
4. 服务短时中断后按目标日期恢复任务；当天首次打开可以触发幂等补齐。任务失败保留已有内容，并提供手动处理入口。
5. 换一餐或活动时展示选定条目及直接影响的菜谱、采购需求，修改只作用于用户核对的范围。库存不随计划推算为实际消耗。
6. 一周计划按需与 AI 讨论，确认后才保存到各日期。日常模板编辑影响后续新安排；批量改变已有日期需要另行展示影响并确认。
7. 时间到达只推进“当前/下一项”的显示，不自动产生完成记录。

自动补缺应区分从未生成、生成失败、主动留空、取消与已删除；后三者不能被任务重新填入。内容停用或食物限制改变后，新增与替换重查适用性，已有未来安排显示需处理状态，历史版本保持。按日期保存的任务与人工改动不能因时区设置更新而重写过去事实。

规则采用修订号和事务，防止两人同时修改造成覆盖；后台自动生成也必须执行同样的权限、约束与冲突检查。

## 7. AI 对话与确认保存

- 会话绑定家庭、宝宝和发起人，页面明确显示讨论日期；同一个人在手机与平板可以继续自己的会话。
- 查询直接回答。日程、菜谱/活动选择、食材和近期偏好等写操作先形成结构化方案，展示具体前后值及影响范围。
- AI 不以聊天内容直接更新禁忌或永久偏好；偏好修改展示有效期限。成员管理、账号、付费以及记录删除不进入首版 AI 执行操作。
- 继续讨论产生新方案版本，旧版本不可确认；只有发起人能确认自己的最终方案，并再次检查当前编辑权限。
- 一次确认在一个数据库事务中完成全部业务修改。任一项冲突或校验失败，整组不写入，返回受影响条目并重新预览。
- 重复点击、断网重试以及提交成功但响应丢失，均取得同一执行结果，不重复改动。
- 家人看到更新后的正式计划及修改人；同步事件和计划变更摘要不泄露私有聊天、未确认偏好或未选择的方案。
- AI 可参考有权读取的已保存文字记录与反馈，并关联实际记录；家庭照片功能已移除。

## 8. 文字记录与回顾

- 一次活动对应一条独立记录，可关联当时计划版本，也可独立补记；发生日期、时段与填写时间分别保存。
- 文字、参与情况、兴趣反馈至少有一项；参与与兴趣独立，感想或时间经过不自动代表完成。
- 替换或取消计划后，记录及其当时内容仍可回看；更新活动库不覆盖历史快照。
- 有效家庭成员可查看正式记录；仅作者和家庭管理员可更正或删除，保留原作者与更正历史。
- 保存失败保留输入，重试不重复创建记录。清空最后一项有效内容时提示补充内容或明确删除整条记录。
- 当前不提供家庭照片上传、附件、缩略图、原图导出和照片额度。原型旧照片流程仅为历史演示，后续实现应移除对应入口。
- 自家计划和文字／反馈记录使用期间保留，不按记录年龄清理；删除后 30 天内可恢复，恢复不改作者及发生日期。取消计划仍作为状态保留，只有明确删除才进入回收站。
- 回收站期限按首次成功删除时间计算，重复删除不续期；恢复前重查成员、权限、截止时间与当前版本。计划已变更时预览合并结果，不覆盖后来安排；记录可通过当时快照独立恢复。
- 删除对象从普通读取、推荐及新 AI 检索中排除；关联实际记录不级联删除。到期清理正文和不再需要的修订内容，操作审计不保留完整正文。
- 记录和计划版本纳入数据库备份与恢复；备份期限与回收站期限分别落实。恢复备份需核对删除截止时间、恢复点后的撤销／删除流水及当前成员权限，未核实前不开放恢复库。

## 9. 内容、天气和最小管理能力

首批内容以“能形成一周实际可用安排”为整理目标，允许重复熟悉的菜谱和活动。每条内容保存适用条件、原料或材料、步骤、具体出处、改编说明与真实核对状态；食物禁忌、进食能力等信息不足时保持未知。详细规则以[内容来源与推荐规则](内容来源与推荐规则.md)为准。

已确认的 11 条家庭菜谱初始均为草稿。导入校验家庭归属、原文和唯一来源，逐条报告结果并支持安全重试；保留草稿不自动启用。核对状态、家庭启用及专业审核独立记录，新版本重新核对影响范围；无适用候选保留待安排，不由 AI 补造事实。

天气优先验证和风天气，按家庭地点与活动时段获取；城市变更后不沿用旧城市数据，缺失或过时明确展示。已选活动不因天气刷新自动被替换。天气归因、缓存和留存期限按实际接入的服务核实。

S1 提供受控的内容导入、校验和版本发布方式，以及查看任务失败、API 用量和存储用量的能力；可以先使用管理脚本或小型内部界面。家庭管理员不自动成为平台内容运营员。S2 再补试用发码、家庭权益及到期管理，S3 补订单与会员码管理。

B0～B4 均属于 S1；完成 B1 不等于首版全部完成。S2～S4 的交付范围见第 2 节，技术方案与会员方案沿用相同编号。

| 批次 | 交付 | 必须通过的检查 |
| --- | --- | --- |
| B0 规格和环境 | 确认规则、核心接口/模型、补齐登录及初始化交互，核实部署条件 | 规则能对应到页面和服务端校验；无真实服务接入的部分明确标记 |
| B1 首条真实流程 | 登录→创建家庭→邀请家人→保存一天安排→手机/平板同步 | 两个测试家庭隔离；奶奶能编辑计划；成员撤销后接口失效；无静默并发覆盖 |
| B2 内容与记录 | 食材、菜谱、活动、来源、日历、文字与反馈、回收站、打印 | 单餐修改保留其他项；同活动多次记录独立；他人不能改记录；重试不重复保存；恢复权限、期限及冲突处理有效 |

| B4 自家验收 | 真机连续使用和备份恢复 | 覆盖工作日与周末；计划、记录与历史版本恢复完整；保存及同步满足实测目标 |

正常网络、推送可用时，跨设备更新暂以保存后 5 秒内为验证目标；实测记录设备、网络和数据规模，不把它表述为已实现的服务承诺。

验收沿用[产品需求](产品需求.md) AC-01～AC-27 中未取消的条目及 AC-32～AC-50，并补充以下规格验收；SPEC-04 保留编号但不执行：

- SPEC-05：更正保留原记录人和更正者；原记录在修改日程、更新内容版本后仍可关联当时内容。
- SPEC-06：保持登录、主动退出、修改密码、恢复账号和撤销成员关系分别验证；私有响应不进入跨用户共享缓存。

- SPEC-08：当邮箱尚未验证时，系统不创建可访问家庭的成员身份；验证码错误、过期、重放或邀请已撤销时，注册不授予家庭访问权；已有邮箱不得因邀请流程被重设密码。

- SPEC-10：当邮件发送失败或未收到时，系统保留可重试流程并执行发送频率限制；邮箱验证码与重置凭证不能互换用途，邮件链接预览或安全扫描不得直接修改账号。

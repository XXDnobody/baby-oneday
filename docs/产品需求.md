# 宝宝计划｜第一版产品需求

版本：v1.0。更新：2026-10-30（Asia/Shanghai）。状态：按用户先固定需求再排期的指令，纳入 [S1-2026-10-30 冻结基线](../specs/baby-plan/baseline.md)，固定主要流程、异常处理、数据留存及验收要求。S2～S4 的未定政策保留阶段边界；工程建议仍需落实。当前交付仍为文档与本地原型，真实服务尚未实现。

本文件是产品范围与业务规则的主文档。[页面结构](页面结构.md)描述如何呈现，[开发规格](开发规格.md)落实权限与实施批次，[接口与数据模型](接口与数据模型.md)给出工程草案。文档分工、对齐记录和待定事项统一见[需求对齐与待定事项](需求对齐与待定事项.md)。

本轮决定（2026-10-29～30）：内容启用范围仅家庭管理员可修改；移除家庭照片上传、保存、展示和导出，保留文字、参与情况与兴趣反馈；活动卡以图文为主，英语音频仅在确认核心需要后补充，视频后置。旧小程序以 4 位成员、全家共用的“五一”家庭为目标；经核查及展示样本，用户已确认首批复用必要基本资料＋全部 11 条个人菜谱草稿，历史计划和流水后置，菜谱补齐缺项后再选择启用。

新增明确决定（2026-10-30）：自家阶段的计划和文字记录在使用期间保留，不按时间自动清理；主动删除后进入回收站，30 天内可恢复。容量与备份成本在上线前核实。本版围绕该决定补全恢复权限、到期及关联记录的处理要求，未将自家政策自动扩展成对外会员承诺。

## 0. 阅读约定与阶段边界

- **已确认需求**：用户已明确的行为与范围，包括邮箱＋密码、平板直接操作、成员权限、AI 预览确认、统一日历与文字反馈记录。
- **设计或工程建议**：交互布局、接口与表结构、验证码形式、超时时长、默认任务时间等实施方案，需在对应模块中验证；不等同于用户逐项确认。
- **待定事项**：对外收费权限、试用及会员留存政策、服务额度等，不能以原型默认值或技术选型代替决定；自家计划与文字记录的保留及 30 天恢复规则已确认。
- **已实现与已验证**：必须另有代码或执行证据。原型的本机保存、演示登录、固定天气与模拟 AI 不代表真实服务。

阶段编号统一为 S1～S4；开发规格中的 B0～B4 是 S1 内部的实施批次，不是额外的产品阶段。

| 阶段 | 范围 |
| --- | --- |
| S1 自家可用 | 邮箱账号与家庭邀请、初始化、模板与共享计划、食材和菜谱、亲子活动及来源、天气穿搭、AI、日历、文字与反馈记录、计划／记录回收站、平板、打印，以及数据库备份恢复 |
| S2 外部试用 | 10～20 个受邀家庭、7 天试用、新家庭初始化、家庭权益和用量、到期查看与导出；开放前明确内容年龄范围、额度和保存政策 |
| S3 收费测试 | 一种家庭会员套餐、经核实的订单、会员激活码、续费、退款和权益管理；29 元／家庭／30 天仅为测试报价 |
| S4 公开推广 | 面向公众的产品介绍、可预览和撤销的公开快照、购买成功直接开通；保留赠送与渠道激活码 |

先实现手动共享计划是 S1 的开发顺序，S1 完整交付仍包含 AI、天气和文字反馈记录。家庭隔离从 S1 建立；自家阶段无需先实现试用兑换或收费。S2 可向受邀家庭展示介绍与示例，不因此开放 S4 的公开分享服务。

现有“家庭大屏”需求统一称为“平板模式”：同一 Web 系统的触屏与大字布局，使用成员账号，无需设备配对，权限随成员。旧稿中的“只读大屏”“手机配对”仅用于追溯历史设计。首版界面围绕一名宝宝，保留宝宝数据关联；多宝宝界面、微信登录、自动照片分析、自动成长评估、自动周报、完整睡眠／进食打卡和衣橱逐件搭配均不纳入 S1 承诺。

本版状态、失败处理和验收细则随 S1 范围纳入冻结基线，后续行为变更按基线的变更规则处理；工程参数与实现建议继续单列。[需求与验收映射](../specs/baby-plan/requirements.md)列出用户故事及验收覆盖；接口名称、技术实现和测试执行结果不在本文件中冒充产品决定。

## 1. 产品目标

帮助家人知道今天怎么安排、具体怎么做，并能随着食材、天气和宝宝的反应灵活调整。通过 AI 讨论今天或一周的安排，再把关键时刻的感想、参与情况和兴趣反馈保存到日历，供日后回顾与规划参考。

第一版先服务用户自己的家庭，宝宝在 2026-10-28 需求访谈时为 17 个月；正式使用以家庭填写的月龄依据为准。最重要的新增价值是帮助照护者知道怎样陪玩、能够持续开展互动，并逐渐理解活动目的和调整方式。饮食、穿搭和平板模式共同组成日常使用流程。

首版支持手机、电脑和平板浏览器直接登录与操作。平板使用家庭成员账号，权限跟随成员，提供适合触屏和大字阅读的布局。账号与数据从一开始按家庭组织，支持邀请其他家庭试用。正式收费在试用验证之后开展。

## 2. 真实问题与设计依据

| 用户描述的情况 | 对系统的要求 |
| --- | --- |
| 旧小程序生成菜单，但没考虑冰箱里还剩的蔬菜 | 排餐参考现有食材和优先消耗意愿；保存食材确认时间 |
| 宝宝近期不爱吃面，家里会临时换成饭 | 可以替换一餐或一种食物，并表达近期偏好 |
| 奶奶觉得看手机菜谱麻烦 | 提供清楚的大字菜谱和适合打印的步骤 |
| 想认真开展早教，但缺少相关知识 | 活动同时解释怎么做、为什么这样做、观察什么、如何调整 |
| 白天主要想安排户外，时间要结合实际情况 | 户外优先，提供室内备选，活动时长保持弹性 |
| 风大、荡秋千时裤脚上移等具体场景容易漏考虑 | 穿搭结合天气、活动方式及出门检查细节 |
| 家人认可减少不必要打断、给宝宝尝试机会，但习惯上会插手 | 平板主页持续呈现少量已达成共识的具体提醒 |
| 希望直接与 AI 聊今天或一周的需求，并调整日常管理数据 | 提供统一对话入口，将讨论整理为可预览、可确认的具体改动 |
| 活动后想留住感想与宝宝反应 | 按日期和每次实际活动保存记录，日历可同时查看计划与回顾 |

用户提到露出脚踝后出现流鼻涕。这是用户观察到的先后情况，产品需求不把它记为已确认的症状原因。

## 3. 家庭成员与日常节奏

| 成员 | 已确认的使用方式 |
| --- | --- |
| 你（爸爸，家庭管理员） | 维护日常资料和计划，管理家庭成员；修改宝宝关键资料、禁忌和自动生成设置，选择家庭提醒 |
| 宝宝妈妈（日常编辑成员） | 可改食材、近期偏好、作息模板及安排，新增记录；参与晚间照护和周末陪玩 |
| 奶奶 | 主要买菜、做饭及部分户外照护；在平板查看、记录、换餐、调整活动与时间，按需使用打印页；与妈妈同为日常编辑成员 |

工作日模板依据用户的真实描述建立：

| 时段 | 日常安排 |
| --- | --- |
| 起床后 | 奶奶准备早餐，宝宝吃早餐 |
| 上午 | 你带宝宝楼下户外，奶奶买菜、准备午饭 |
| 中午 | 午饭及午睡，你负责带睡 |
| 午睡后 | 下午茶，奶奶带宝宝户外 |
| 约 16 点 | 你接替奶奶，奶奶回家准备晚饭 |
| 约 17 点 | 你带宝宝回家吃晚饭 |
| 晚饭后 | 宝宝妈妈陪玩 |
| 约 19 点及之后 | 洗澡、室内陪玩，宝宝妈妈带睡 |

周末主要由父母带宝宝玩，奶奶主要负责做饭。早餐、午睡等未提供的具体时间由家庭配置；19 点等已有时间也作为可调整模板。

家庭管理员不是平台内容运营员，也不能查看其他成员的私有 AI 聊天或接管其账号。内容启用范围和共同提醒均由家庭管理员管理；妈妈、奶奶可在已启用内容中换餐或调整活动，不能改变启用范围。

### 3.1 必须完成的用户流程

| 流程 | 起点与主要操作 | 完成时应得到的结果 |
| --- | --- | --- |
| 第一次准备家庭 | 管理员验证邮箱并登录 → 保存必要资料 → 核对模板和内容 → 准备今天 | 只有一份本家庭的正式日计划；信息不足的餐食明确待安排，不生成已确认的禁忌或菜谱 |
| 家人加入和日常使用 | 打开家庭邀请 → 本人账号登录或注册 → 核对家庭与角色 → 加入 | 妈妈、奶奶在手机和平板能按本人权限操作，原家庭数据和私人聊天不会混入 |
| 临时调整一餐或活动 | 选具体日期和条目 → 查看可用替代及影响 → 保存 | 只改变本次确认的条目和直接依赖；家人获得同一正式版本 |
| 和 AI 安排一周 | 明确家庭与日期 → 讨论 → 查看最后一版改动 → 一次确认 | 整组成功保存，或整组失败并保留草稿；没有半周更新成功、另一半失败的未说明状态 |
| 记录和回顾 | 从安排或日历进入 → 填实际日期与至少一项反馈 → 保存 | 记录可单独找到，保留原作者和当时安排；后续计划修改不改写已发生的记录 |
| 删除与恢复 | 有权限的成员明确删除 → 在回收站查看截止时间 → 30 天内恢复 | 恢复原条目或记录及其归属；遇到当前计划变化时先核对，不覆盖后来保存的内容 |

### 3.2 日期、字段与缺失信息

| 数据 | 首版要求 |
| --- | --- |
| 宝宝 | 称呼和可核对的月龄依据；真实生日可选，或填写月龄与确认日期。不从演示年龄倒推生日，不接受未来出生日期 |
| 家庭 | 当前家庭、默认天气城市及其时区明确；家庭默认设置由管理员维护，某次活动的地点和时间沿用日常安排权限 |
| 食物限制 | 区分“已确认没有已知限制”“有具体限制”“尚未确认”；空列表不能自动视为已确认无禁忌；旧记录与当前确认分别保存 |
| 计划条目 | 家庭、宝宝、计划日期、类型、时间或时段、内容及照护者；未指定具体时刻可保留时段，未指定照护者显示待分配 |
| 文字记录 | 发生日期、填写人和填写时间；文字／参与／兴趣至少一项，未填项保留未知。实际发生日期不能晚于家庭当前日期；未来事项写入计划 |
| 偏好与库存 | 偏好说明作用范围和有效期；库存保留确认人／时间及粗略余量。未知、缺货、未确认是不同状态 |

今天、明天及记录日期按家庭时区解释；AI 一周方案须显示具体起止日期。发生日期与填写时间分开，之后更改默认城市或时区不追溯改写历史记录的日期和内容快照。具体字段长度、格式限制和可配置参数在工程契约中确定。

## 4. 首版功能

### 4.1 今日安排

- 使用工作日、周末模板，显示当天安排、下一项活动和照护者。
- 在家庭已认可的内容与规则范围内自动形成日常安排并展示。
- 初次使用准备今天的安排；之后每天晚上准备次日，一周计划按需讨论并确认。具体夜间时刻属于可配置的工程建议，不能覆盖已保存的人工修改。
- 支持调整时间、换餐、替换活动、切换室内外方案。
- 一次局部修改保留其他安排；需要连带改动时清楚展示影响范围。
- 每次变更记录修改人和更新时间，所有家庭成员看到同一份最新安排。
- 到达计划时间仅改变时间线位置；“已完成”以家庭实际反馈为准。
- 今日页与日历使用同一份正式安排；AI 对话中的待确认方案单独展示。

### 4.2 辅食与食材

- 排餐前简单勾选现有食材、需要优先吃的食材，可标注“够一顿”“还有不少”等粗略余量。
- 食材信息保留确认时间；时间推移或计划经过多次替换后，允许家人重新确认。
- 菜单考虑已确认的食物禁忌、偏好和近期接受程度。
- 支持单独换一餐、换某项食材、暂时减少一种食物的安排。
- 家里已有食材与需要购买的食材清楚区分，数量不确定时明确提示需要核对。
- 菜谱以清楚的原料、准备工作和分步做法呈现，提供大字查看和打印入口。
- 旧资料首批范围已确认：五一必要基本资料＋全部 11 条个人菜谱草稿，历史计划和流水后置。排敏旧状态及偏好需确认当前情况后用于安排；草稿保留不自动启用。

### 4.3 亲子活动与家长指导

- 采用专门亲子活动与日常场景互动相结合的方式，白天为主，户外优先。
- 每个活动说明所需材料、场地、步骤、目的、观察点、调整方法和来源。
- 户外活动提供出门前能记住的一两个简单玩法，手机可随时补充查看。
- 结合月龄、场景、已知兴趣和历史反馈筛选内容；允许跳过、换玩法和改期。
- 活动时长依据当天实际情况调整；访谈未确定每天必须投入的固定分钟数。
- 可选反馈为“喜欢、没兴趣、太难”等，可补感想，并关联某天的某次活动；缺少反馈保持未知。
- 单次反应作为调整线索，避免把偶然反馈固化为长期能力判断。
- 感官探索、动作游戏、语言及英语亲子互动可进入内容筛选范围；每个具体条目需要核对适用条件。活动卡以图文为主，说明配图属于内容素材；英语示范音频仅在确认核心需要后补充，视频后置。

### 4.4 天气与穿搭

- 按城市天气、当天时段和活动场景推荐衣物类别与组合。
- 结合温度、风、降雨等可获得的数据，显示天气更新时间。
- 提供与活动相关的检查细节，例如坐秋千时裤脚是否上移。
- 2026-10-31 用户新增衣物搭配需求：支持拍照/相册上传到家庭衣服库，根据天气、活动时段和场景推荐实际衣物组合，排除待洗、不合身、已收起的衣物，显示推荐理由及缺项。详见 [CR 衣物搭配](../specs/baby-plan/wardrobe.md)；原 S1 冻结副本保留。
- 天气数据缺失或过时时，展示数据状态和既有安排，避免以过时数据冒充当前情况。

### 4.5 平板使用、家庭提醒与打印

- 平板直接登录家庭成员账号，家人可在平板上查看、记录和操作。沿用同一家庭的数据与成员权限，无需手机配对。
- 平板模式以大字、清楚的层级和触屏按钮呈现内容，横屏和竖屏均可使用；需要时可切回普通视图。放在公共位置时也便于抬眼查看。
- 显示当前计划时段、下一项安排、饮食与穿搭摘要，以及少量家庭共同提醒。
- “本周共同练习”由你选定，体现家人已经认可的照护方式，并可查看简短理由和来源。
- 日常内容自动显示，新照护原则经过确认后进入提醒范围。
- 平板可直接看大字菜谱、打开日历、记录活动与反馈；有编辑权限的成员可换餐、调整活动和时间。打印页提供当天安排和所选菜谱。
- 打印是生成当时的内容快照，应标明适用日期和更新时间。后续变化在平板、手机中同步。
- 屏幕以计划为主，AI 修改保存成功后同步正式安排。关键节点的实际记录纳入首版；完整记录入睡、起床、每餐完成等状态仍属于后续评估范围。

### 4.6 AI 总入口与对话式管理

已确认的行为：

- 通过自然语言讨论、生成和调整今天或一周的安排，范围涵盖日程、菜单、活动及相关食材和偏好等日常管理数据。
- 2026-10-31 根据实际使用澄清：内容库为空仍可生成具体菜单和活动草案；未知食材列采购或核对，缺天气时给有条件的户外建议和室内备选。家长聊天中给出的作息可直接用于本次规划。新 AI 建议须标明来源，确认后可保存为本次采用的日常安排，不因此自动创建、启用或宣称核对了内容库条目。自动任务对已启用内容的限制继续保留。
- 查询和讨论直接回复。涉及写入正式业务数据时，先展示改动清单，由用户一次确认后统一保存。
- 用户可以在确认前继续缩小范围、更换方案或保留指定安排；确认对应最终展示的那一版改动。
- 保存结果进入共享计划，供手机、日历、菜单和平板读取；待确认方案保留在讨论中。
- AI 聊天与未确认方案仅发起人可见，家庭管理员也不能据成员管理权限查看；家人共享确认后的正式计划，不默认公开聊天原文。

业务约束（与开发规格一致）：

- 明确显示正在讨论的宝宝、日期范围及相关条目；改动清单包含具体前后值、直接影响和偏好期限。
- “最近不吃面”等表述先作为待确认的偏好建议，并显示生效期限；一次聊天中的描述不直接变成长期家庭资料。
- 方案等待确认时，如家人修改了相关安排，展示最新内容并重新核对受影响部分；重复点击或请求重试只执行一次。
- 保存成功、待确认、保存失败分别呈现。AI 不可用时仍可查看和手动调整已有安排。
- 已启用的模板自动安排沿用既有规则；新对话方案须经确认，后台生成也不能覆盖已保存的人工选择。
- 确认保存沿用成员对具体操作的权限；成员管理、账号、付费和记录删除不进入首版 AI 执行范围。

交互设计建议：各管理页提供固定“AI 助手”入口，今日页另设醒目入口；电脑用侧边面板，手机用完整对话页。同一成员跨页继续自己的会话，改动清单按日期与类型组织。具体布局随原型与真机评审完善。

### 4.7 统一日历与关键节点记录

- 一个日历贯穿未来计划、当天执行和历史回顾；过去日期可看实际记录及当时安排。
- 从活动卡进入时关联具体一次安排，也可独立记录临时事件或补记过去的事情。
- 记录发生日期与填写时间分别保存；具体时刻选填，也可只标上午或下午。
- 文字感想、参与情况、兴趣反馈至少填写一项；参与与兴趣分别表达，未填写保持未知。感想或时间经过不自动代表活动完成。
- 同一活动多次开展时分别记录。后续更换活动、取消安排或更新内容库，不覆盖历史记录及关联的当时版本。
- 获授权家庭成员可查看正式记录；仅记录本人和家庭管理员可更正或删除，保留原作者和更正历史。
- AI 可参考有权读取的已保存文字与反馈并注明记录依据，推测与家长原话分开。
- 家庭照片上传、附件、相册展示和照片导出已退出当前范围；不再建立纯照片记录、照片额度或照片备份要求。活动卡和菜谱的说明配图继续作为内容素材使用。

交互建议：月历用于选日期和概览，选中日期显示时间线；一周方案提供按天摘要。记录表单保留文字、参与和兴趣字段，删除最后一项有效内容时需补充内容或明确删除记录，不能静默保存空记录。

自动照片分析、自动成长评估和自动周报均不纳入 S1。

### 4.8 计划和文字记录的保存、删除与恢复

以下保留原则和 30 天恢复期限已由用户确认；边界处理为本版细化要求。

- 自家使用期间保留计划和文字／反馈记录，不按记录年龄自动清理。容量不足时明确提示并处理容量问题，不通过静默删除旧记录解决。
- 回收站覆盖正式计划条目和文字／反馈记录。取消某次安排只标记取消，仍可回看；明确删除才移入回收站。整户销毁、账号删除、AI 会话回收及素材库回收不由本条自动新增为功能。
- 删除计划沿用日常计划编辑权限；删除或恢复记录仅限原作者和管理员。回收站只列出本人当前有权恢复的对象，成员资格已撤销时不能访问。
- 删除后，普通日历、列表、详情、历史接口、推荐及新 AI 检索不再返回该对象的正文；关联记录独立保留自己的当时计划快照。删除计划不级联删除实际记录，也不自动恢复它们。
- 恢复期限从服务端首次删除成功时起计 30 天，展示按家庭时区换算的准确截止时刻。重复删除请求不延长期限；恢复不改变原作者、原发生日期或原归属。
- 恢复时重新检查权限、截止时间和当前版本。原计划已变化时先显示恢复位置与当前安排，确认后合并，不能覆盖后来保存的条目。原计划已删除的文字记录可凭保存的快照独立恢复。
- 到期后不再提供恢复，随后清除该删除对象及其不再被保留记录需要的正文、修订内容。必要操作审计仅保留对象标识、动作、人员及时间等信息；不把完整正文永久留在审计中。
- 回收站期限与数据库备份保存期分别管理。备份保存周期、清除时延及恢复目标在 E-03／E-06 中落实；不能承诺删除后所有备份副本立即消失。恢复备份后先核对删除期限和成员权限，再开放使用，防止过期删除数据重新出现。

### 4.9 保存、断网和并发的统一规则

| 情况 | 必须呈现的行为 |
| --- | --- |
| 正在加载、从未加载、列表为空 | 分别显示加载、需要联网／重试、暂无内容；服务失败不能显示成“没有记录” |
| 正在提交 | 显示待保存并防止重复操作；只有收到可核对的服务端成功结果才显示已保存 |
| 提交后响应丢失 | 查询同一次操作的结果；确认未完成后再重试，不盲目创建第二条记录或第二份计划 |
| 临时断网 | 保留当前会话已加载内容和未提交输入，标明离线与最后同步时间；不显示成已共享保存 |
| 恢复联网 | 重新校验身份并取得最新版本；存在本地未提交改动时展示差异，由成员确认重试，避免自动覆盖 |
| 家人同时修改 | 保留本次输入并显示最新内容及冲突位置；基于新版本重新核对，失败不能造成部分业务更新 |
| 退出、切换账号或成员权限撤销 | 停止私有内容展示与访问；上一身份的未提交内容不自动带入或提交到另一账号、家庭 |

首版不承诺关闭浏览器后仍能离线打开全部数据，也不提供无提示的离线写入队列。页面自身长时间停留不代表其他设备已经同步。

### 4.10 自动安排与手动修改的边界

- 初次完成设置准备今天，之后每晚准备次日；重复触发、重启恢复或当天补齐都针对同一家庭、宝宝和日期，不创建重复日计划。
- 模板变更影响之后尚未生成的安排。已保存日期、人工选择及已确认 AI 结果保持原状；要批量调整既有日期时另行展示影响并确认。
- 自动任务只补缺，不把已取消、主动删除或人工保留空白的条目重新当作待填空位；恢复操作也不触发过去日期的自动补写。
- 找不到合适且已启用的菜谱或活动时显示待安排及原因，可查看其他已核对候选或稍后再处理；不以未经核对的生成内容凑齐整天。
- 新食物限制、内容停用或适用条件变化后，新生成与替换须重新核对。已有未执行安排提示受影响的条目和替换入口，不静默重排全日；历史记录保留当时版本。
- 单次换餐不自动改变长期偏好。选择“近期少安排”时展示起止日期与作用范围，到期后不再用于新推荐，历史安排不回写。

### 4.11 平板、打印与可用性要求

手机、电脑和平板使用同一份业务数据，页面应能在实际验收设备的横竖屏下完成关键操作，不因布局变化隐藏已授予的权限。状态除颜色外还须有文字，保存或删除结果明确可辨；错误提示定位到具体字段并保留有效输入。

平板的大字菜谱、活动详情和返回今日页入口应适合照护现场操作。打印以 A4 黑白可读为初始验证目标，原料与完整步骤不得被裁切，保留日期、版本和必要来源标记。常亮、字体大小和跨设备 5 秒同步目标属于待真机验证的工程条件，不能因静态原型展示而认定通过。

## 5. 内容如何进入推荐

本节原则已由用户确认，完整资料目录、来源链接、推荐规则和待办见[内容来源与推荐规则](内容来源与推荐规则.md)。确认来源方向不等于具体条目已经核对或专业审核。

1. 选取可核对的资料，保留标题、作者或机构、原始链接、版本或日期、具体章节或段落、适用范围及使用方式。
2. 区分一般指南依据、菜谱或活动的做法来源、家庭经验和当天选择理由；原文摘要与本地改编分别标注。
3. 饮食以中国营养学会喂养指南、卫健委营养喂养评估指南为基础，WHO 资料补充核对。菜谱从家庭实际做法、可核实的旧小程序条目和专业机构公开食谱整理；先核对适用性，再看全天搭配，再按库存、近期偏好和准备条件排序。
4. 活动以卫健委分月龄交流与玩耍资料、WHO 回应性照护原则、UNICEF 具体玩法为起点；结合实际能力、兴趣、照护者、场地材料和当天状态选择，保留改编说明，不以完成数量或回答正确率评价宝宝。
5. 天气以和风天气为优先接入候选，按实际城市或地点和活动时段取得数据；穿搭参考儿科照护资料，再结合活动量、风、停留方式及家庭反馈形成场景建议。服务可用性、费用和当地表现仍需验证。
6. 页面先说明怎么做，再解释今天为什么选它，展开后能够核对原文、改编及实际用到的家庭记录或天气数据。出处核对、家庭启用、专业审核分别记录。
7. 初次设置时，家庭了解并启用可自动安排的内容范围；新的家庭原则单独确认。日常生成从可用内容中选择、组织和解释，更新依据后保留版本。

用户书架中的《儿童感觉统合训练》《从出生到3岁》《无条件养育》《全脑教养法》《美国儿科学会育儿百科》等属于阅读背景和候选参考。当前仅识别了封面，尚未逐本审阅；引用前核对到实际章节。内容素材的出处与使用许可随条目保存。

### 5.1 内容进入家庭使用的条件

| 状态 | 可做什么 | 进入下一步前的要求 |
| --- | --- | --- |
| 原始草稿／待补齐 | 保留原文供内容整理与核对，显示缺项 | 补完整做法、原料／材料、用量依据、适用条件和具体来源；不能自动成为餐食候选 |
| 已完成对应内容核对 | 可供管理员审阅，展示实际核对范围 | 明确家庭适用条件和内容版本；专业审核另记，不能从字段齐全推断已获专业审核 |
| 家庭已启用 | 在当前条件仍适用时参与手动选择与自动安排 | 每次使用仍检查当前限制；家庭启用不绕过缺项和适用性校验 |
| 停用或待重新核对 | 保留已用版本和历史依据 | 新增、替换与自动安排不得继续采用；已排入的未来条目提示处理，不改写历史 |

来源核对、家庭启用、专业审核是独立事实。发布新的原料或做法版本后，不能静默继承旧版本全部核对结论；历史计划仍引用原版本。家庭实际做法可以注明家庭来源，没有公开链接不自动判为错误，但必须如实说明依据和未核对部分。

首批 11 条个人菜谱全部以草稿复用，缺失数值及加工形态不由 AI 补造；旧“6 个月”默认值和“通过”状态不直接转成当前适用结论。初始化需核对条数、原文及家庭归属，重复处理同一批次不生成重复菜谱；失败有逐条结果可追查。家庭草稿不得因导入而成为公开系统内容。

## 6. 账号、试用与家庭会员

- 一份家庭空间包含成员关系、宝宝资料、偏好、食材、安排、日历记录。登录会话属于独立用户账号，访问家庭时再核对成员关系；AI 会话与方案关联所属家庭和发起人，聊天和草稿仅本人可见，正式计划按成员权限共享。
- 家庭之间的数据独立；新家庭能够完成初始化并看到自己的安排。
- 你为家庭管理员，妈妈和奶奶均有日常编辑能力，可改食材、近期偏好和作息模板；宝宝关键资料、禁忌及自动生成设置仅你可改。奶奶可直接在平板登录、记录、换餐和调整活动与时间。常用设备保持登录；相同账号在手机、电脑和平板拥有相同权限。
- 先自家持续使用，再邀请 10～20 个外部家庭体验 7 天；之后测试一种付费家庭会员。一个家庭购买、成员共享权益，邀请家人不另收费。
- 试用邀请码负责免费试用，会员激活码负责开通一定期限的服务，家庭邀请链接负责加入已有家庭。三者独立验证，兑换会员不授予其他家庭的访问权限。
- 会员覆盖个性化日常计划、AI 讨论与确认修改、家庭协作、平板、日历与文字反馈记录；AI 使用设定明确额度，不承诺无限用量或终身服务。
- 兑换前确认目标家庭、权益及生效后的到期时间。激活码一次使用；续费从未到期权益末尾累计，已过期则从新开通时间计算。
- 试用或会员到期后停止新增付费服务，已有安排与记录保留查看和导出。记录保存期限及清理通知在试用或购买前告知，不能把导出已有数据作为续费条件。
- 对外分享示例或经过预览的去身份信息快照，默认去掉宝宝姓名与地点；推广链接引导新用户创建自己的家庭，家庭内部邀请仅供照护者加入。
- 29 元／家庭／30 天仅为待验证测试报价；正式价格、AI 额度、数据保存期限、到期后的免费新增功能边界和支付退款方式仍需确定。
- 首版使用邮箱＋密码，首次验证邮箱，常用设备保持登录；忘记密码通过已验证邮箱重置，重置后旧会话失效。发信服务与投递、会话工程参数、邮箱不可用时的人工恢复、外部试用年龄范围及成员邀请有效时长仍需落实。完整商业规则和阶段验收见[分享与家庭会员方案](分享与家庭会员方案.md)。

### 6.1 账号与初始化的完成条件

S1 首位管理员通过受控入口创建家庭，其余成员受邀加入。注册验证、用户身份与家庭成员关系分别成立；验证邮箱不提前授予家庭访问权。邀请接受时再次检查用途、目标家庭、角色、过期及撤销状态；已加入成员重复打开邀请不产生第二份成员关系。最后一位管理员不能通过移除或降级操作使家庭失去管理者。

初始化可保存进度并继续，重复提交不创建另一份家庭或宝宝。未确认月龄依据、食物限制或可用内容时，可查看模板与待补充项，相关餐食不能显示为已核对的正式推荐。旧资料导入与用户确认的当前资料分别显示；导入 11 条草稿不能替代内容启用。成员接受邀请后进入已有家庭，不能重置其初始化资料。

## 7. 验收场景

以下验收场景把需求转为可检查的行为，保留原有编号；属于验收设计，不表示已经执行或通过。S1 对应 AC-01～AC-27 中未取消的条目及新增 AC-32～AC-50，并包括开发规格 SPEC-01～SPEC-10 中未取消的条目；AC-28～AC-30 在 S2／S3 按权益类型执行，AC-31 在 S4 执行。

| 编号 | 场景 | 通过条件 |

| AC-01 | 普通工作日打开系统 | 显示家庭模板对应的日期、安排、下一项活动及内容更新时间 |
| AC-02 | 冰箱仍有蔬菜 | 排餐参考已确认食材和优先消耗标记；待购物清单清楚可核对 |

| AC-06 | 没有记录活动反馈 | 系统保持反馈未知；时间到了不自动记为完成 |
| AC-07 | 奶奶在平板查看和做饭 | 登录后可直接打开大字菜谱、记录本次情况，所选菜谱能打印为可执行的步骤 |
| AC-08 | 家庭共同提醒 | 显示已经启用的具体做法，能查到理由或约定来源 |
| AC-09 | 父母同时修改同一餐 | 后提交的人看到冲突与最新内容，可重新选择，不静默覆盖对方修改 |
| AC-10 | AI 或天气暂时不可用 | 既有安排仍可查看；新建议显示真实可用状态和时间 |
| AC-11 | 平板短时断网 | 标明离线和最后同步时间；联网后取得最新安排 |
| AC-12 | 使用另一个家庭账号 | 页面、接口、打印和同步通道均只能取得获授权的家庭数据 |
| AC-13 | 在平板登录与操作 | 无需配对；同一成员在手机与平板的可用操作一致，写操作按成员权限校验，会话失效后在本机重新登录 |
| AC-14 | 修改后重新打印 | 新打印页包含最新内容，日期和更新时间便于识别旧纸张 |
| AC-15 | 与 AI 讨论本周菜单和活动 | 日期范围明确；生成的改动可继续讨论，确认前正式安排保持原版本 |
| AC-16 | 确认 AI 最终方案 | 仅执行最终预览中的改动；成功后日历、菜单、今日页和平板读取同一版本，重复提交不重复写入 |
| AC-17 | 确认前家人修改相关安排 | 识别受影响内容，展示最新版本并重新核对，不静默覆盖 |
| AC-18 | 从日历选择未来、今天或过去 | 分别查看安排、记录入口和历史记录；能展开过去关联的计划 |
| AC-19 | 活动结束随手记录 | 可仅填文字、参与情况或兴趣反馈中的一项，保存日期、记录人和关联活动 |
| AC-20 | 补记临时外出，同一活动多次开展 | 可记录未计划事项及过去日期；同一活动的各次记录互相独立 |
| AC-21 | 后续更换活动或取消安排 | 原记录和所关联的当时安排可回看，不被新内容覆盖 |
| AC-22 | 当天没记录，或仅写感想 | 无记录显示“暂无记录”；感想不自动产生完成状态或宝宝表现评价 |
| AC-23 | 已取消：照片上传与重试 | 2026-10-29 用户移除家庭照片功能；保留编号追溯，不列入当前验收 |
| AC-24 | 其他家庭访问记录或 AI 方案 | 列表、详情和方案执行均受家庭及成员权限约束 |
| AC-25 | 查看一条餐食或活动推荐的依据 | 能区分一般原则、具体做法来源、改编和当天理由，定位到实际支持结论的原文及家庭记录 |
| AC-26 | 更换天气城市、外出时间或活动方式 | 使用正确地点与活动时段的数据重新核对受影响的穿搭；数据无效时明确标注，不沿用旧地点冒充当前依据 |
| AC-27 | 内容仅经过家庭认可或出处核对 | 页面如实展示相应状态，不显示未经实际完成的专业审核 |
| AC-28 | 一个家庭购买后家人分别登录 | 共用会员权益，成员操作权限不因购买或兑换而提升；加入家人不另收费 |
| AC-29 | 同一码并发兑换或网络重试 | 仅一个家庭成功开通，重试不重复延长；家庭邀请不能用作会员开通凭证 |
| AC-30 | 试用或会员到期 | 服务端与后台任务停止新增付费服务；已有内容在告知的保存期限内可查看和导出 |
| AC-31 | 用户分享计划给其他家庭 | 分享前预览公开内容；默认不含宝宝姓名、地点或家庭内部访问凭证 |
| AC-32 | 初始化中断后继续或重复提交 | 当管理员重新打开设置时，系统应恢复已保存进度；重复提交不增加第二份家庭、宝宝或日计划；邀请成员不得覆盖现有设置 |
| AC-33 | 邀请过期、撤销、已加入或并发接受 | 当邀请状态发生变化时，系统应在最终加入前再次检查；同一身份和家庭只建立一份关系，失败不授予访问权，也不显示家庭私有内容 |
| AC-34 | 旧食物状态或限制尚未确认 | 当仅有旧“通过”或空限制列表时，系统应保留当前确认未知状态，相关推荐仍待核对，不生成已确认的禁忌或允许名单 |
| AC-35 | 草稿、停用内容或新版本进入选择 | 当内容不满足核对、家庭启用或当前适用条件时，系统应拒绝自动采用并说明原因；发布新版本不覆盖历史或自动继承审核结论 |
| AC-36 | 夜间任务重试及主动留空 | 当任务重启或再次补齐日期时，系统应复用同一日计划，保留人工、AI 已确认、取消、删除及主动留空状态，不重新填入已移除的条目 |
| AC-37 | 修改模板或短期偏好到期 | 当模板保存或偏好到期时，系统应将变化用于后续新安排；既有计划保持，批量调整需另行预览确认 |
| AC-38 | 所有候选都不满足条件 | 当无适用且已启用的条目时，系统应显示待安排和缺失条件，不虚构菜谱、来源、天气或已知家庭事实来凑齐计划 |
| AC-39 | 断网期间编辑后重连 | 当恢复网络时，系统应先重新鉴权并读取最新版本，保留本人的未提交输入供核对；未获服务端确认前不显示已保存，不自动覆盖家人修改 |
| AC-40 | 写入成功但响应丢失 | 当用户查询结果或重试同一次提交时，系统应返回同一持久结果，记录、计划及 AI 整组修改均不重复产生 |
| AC-41 | 移除成员或改变当前身份 | 当成员被移除、退出或切换账号时，系统应停止旧家庭私有内容访问和通知；原有记录作者保持，未提交内容不带入新身份 |
| AC-42 | 自家记录达到较长保存时间或容量紧张 | 当记录变旧时，系统应继续保留；容量紧张时给出状态和处理入口，不以静默清理旧记录代替容量处理 |
| AC-43 | 删除与取消安排、回收站可见性 | 当明确删除成功时，系统应从普通读取及新推荐／AI 检索中隐藏正文，仅向有恢复权限者展示回收站及截止时间；取消安排仍可回看，实际记录不被级联删除 |
| AC-44 | 30 天内恢复计划或记录 | 当仍有权限的成员在截止时刻前恢复时，系统应保留原作者、发生日期及快照；计划已有变化须先核对，重试不新增副本或覆盖新安排 |
| AC-45 | 恢复期限已过或重复删除 | 当服务端时间达到截止时刻时，系统应拒绝恢复并按清理流程移除正文；重复删除不重置 30 天期限，不通过普通历史接口读到过期内容 |
| AC-46 | 未来实际记录、错误月龄依据或空记录 | 当输入未来发生日期、未来生日或清空全部有效反馈时，系统应定位错误并保留其余输入，不保存为已发生事实；仅月龄时不补造生日 |
| AC-47 | 首批 11 条草稿重复导入或部分失败 | 当处理已确认批次时，系统应保持家庭归属和原文，给出逐条结果；重复处理不增加第二份草稿，部分失败不显示整批已完成，所有条目初始未启用 |
| AC-48 | 共享平板或打印多页菜谱 | 当在验收设备横竖屏操作或打印时，系统应保留关键操作及权限；状态有文字说明，纸张含完整步骤、日期和版本，长步骤不被裁切 |
| AC-49 | 移除或降级最后一位管理员 | 当操作将使家庭没有管理员时，系统应拒绝并保留原关系；并发操作也不能绕过该限制 |
| AC-50 | 从数据库备份恢复 | 当恢复副本准备开放时，系统应先验证计划、记录、作者、私有会话权限及删除期限；核对恢复点之后的撤销／删除操作，无法确认时保持隔离并处理，不直接恢复过期删除数据的可见性 |

会员续费、退款、额度与凭证状态的详细场景见[分享与家庭会员方案](分享与家庭会员方案.md) MB-01～MB-11；其中 MB-08 的家庭邀请失效场景从 S1 就需验证，其余按对应商业阶段执行。[正式测试计划](../specs/baby-plan/test-plan.md)已编制，详细用例与执行证据在对应批次补齐，原型报告不能替代服务端验收。

## 8. 试用如何判断是否有用

建议先覆盖多个工作日及至少一个周末，实际观察：家人是否主动查看平板、奶奶是否能照着菜谱准备、父母是否能直接开展活动、临时改餐是否省事、AI 改动预览是否容易核对、能否轻松记录并找回一次活动，以及你每天需要额外维护多少内容。

试用结果采用使用行为、简短反馈和具体案例判断。宝宝的发展表现作为家庭观察内容，不作为软件短期效果的承诺。外部首轮按 10～20 个家庭、7 天试用执行，记录一周后持续使用、多位照护者参与、实际服务用量和支持负担；随后观察试用转付费与真实续费。量化成功门槛待首轮数据支持后制定。

# B2 本地实现与验证

日期：2026-10-31（Asia/Shanghai）。版本标记：`local-b2-2026-10-31`。沿用 A「日常工作台」，继续使用 B1 的账号、家庭授权、事务、版本、幂等、SSE 与轮询。入口为本机 3000；测试应用独立使用 3001 和 5433 测试库。

## 已实现能力

- 食材有现有／缺货／未知、未知／少量／够用的粗略余量、优先使用与服务端确认时间。整批确认使用快照修订，家人更新后保留输入，明确载入最新版本再编辑。不会按计划扣库存或据此判断新鲜度。
- 近期偏好区分喜欢、暂避和备注，可用于饮食／活动，有起止日期，可修改或提前结束。每次最多 91 天；按所选安排日期判断是否生效，与食物禁忌分开。沿用 B1 工作日／周末作息模板，不追溯重写已有计划。
- 全部 11 条菜谱从原审阅 JSON 转成未启用草稿，完整保留 74 项原料、原用量、51 步、原提示及映射候选；原始结构另存于第 1 版。逐条保存成功／失败／重试次数，SQL SAVEPOINT 隔离单条失败。相同请求重放相同结果；独立重试使用新请求键；唯一导入键保证不增加副本、不覆盖人工编辑。
- 另有 2 张本地整理的活动草稿和自绘玩法示意 SVG，均未启用，不标成已审阅的外部资料。菜谱与活动可新增、编辑新版本，查看指定旧版本、具体出处、版本／日期、章节、摘要、改编、适用条件及真实核对状态。
- 家庭认可、出处核对、专业审核分别保存。新版本取消启用，编辑器要求重新确认本次核对；只有管理员能修改启用范围。菜谱须针对当前宝宝食物资料修订核对，食物限制未知时不进入餐食候选。旧月龄与旧食材“通过”均不升级为当前结论。
- 手动安排可选择已启用且符合当前月龄、场景、食物资料和期限偏好的具体内容版本。库存与明确文字匹配的喜好只用于排序；暂避会排除匹配候选。没有候选时可明确保存“待安排”。条件变化会提示核对既有未来安排，保留原版本。
- 当天采购／用量核对从实际采用的菜谱与当前库存派生，区分缺货、未知与粗略余量待核对，保留原用量和菜谱版本；改一餐只改变相应派生需求，不改其他安排。
- 家庭管理员可保存已认可的共同提醒，成员只读；页面显示家庭约定来源、记录人、确认时间和版本，当日打印保存当时的提醒。
- 统一日历串联未来计划、当日安排和历史记录，取消、计划和记录数量分开。时间经过不写完成状态，也不推断兴趣或能力。
- 文字记录可关联当前可读的计划版本，也可独立补记。文字／参与／兴趣至少一项，不接受未来发生日期；同一活动用不同请求键多次记录会分别保存，同键重试不重复。
- 记录保留原作者、发生日期精度、最初计划与内容快照、更正人及更正说明。仅原作者或管理员可更正、删除和恢复；管理员更正他人记录须说明。家人可回看记录与更正历史。无照片功能。
- 取消安排仍在日历；删除才进入 30 天回收站，不级联删除实际记录。计划恢复须先预览当天修订；同类同时段已有新安排或预览后有变化时拒绝恢复，不覆盖后来安排。恢复保留原标识、作者和快照。
- 重复删除不延长期限；恢复及幂等重放重新授权。截止时刻及之后普通正文、历史、回收站和恢复均受限制，不依赖清理任务是否已运行。已删除计划的旧打印正文也不可绕过读取；有效记录中的独立历史快照继续可读。
- `npm run trash:purge` 显式清理到期删除正文、旧版本和幂等结果正文，保留审计及 tombstone。与恢复使用相同家庭锁并重新检查截止时间，不按记录年龄清理有效旧记录。单次处理最多 20 个有到期内容的家庭，可重复执行；本机未建立定时清理任务。
- 当日安排和指定菜谱版本可生成固定打印快照。授权读取与打印前重新检查，页面定时／重新可见时也复核访问。A4 黑白版保留原步骤、日期、版本、生成时间、快照标识与每页页码。页面支持 Chrome 页边距页脚；其他实际浏览器和纸质设备仍待验证。

## 迁移与接口

只新增 `002_b2.sql`、`003_b2_reminders.sql`、`004_b2_expired_body_cleanup.sql`，未修改已应用的 `001_b1.sql`。开发库迁移不重置已有账号或家庭。完整契约在 `src/shared/contracts.ts`、`src/shared/b2.ts`，路由在 `src/server/b2-http.ts`。

相对 `H=/api/v1/households/{householdId}`：

| 接口 | 用途 |
| --- | --- |
| GET／PUT H/pantry | 读取／确认食材快照 |
| GET／POST H/preferences；PATCH／DELETE H/preferences/{id} | 日期有效偏好与提前结束 |
| GET／POST H/content；GET／PATCH H/content/{id} | 内容列表、创建、查看及新版本 |
| GET H/content/{id}/versions/{n} | 具体历史内容版本 |
| GET／PUT H/content-settings | 管理员启用范围 |
| GET／POST H/content-imports | 逐条导入结果；POST `{ids:["R01",…,"R11"]}`，活动 A01／A02 |
| GET／PUT H/agreements | 家庭共同提醒 |
| GET H/calendar?from=…&to=… | 每次最多 93 天的计划／记录标记 |
| GET／POST H/records；GET／PATCH／DELETE H/records/{id} | 按次记录、详情、更正和删除 |
| GET H/records/{id}/revisions；POST H/records/{id}/restore | 更正历史与恢复 |
| POST H/plan-items/{id}/cancel 或 resume；DELETE H/plan-items/{id} | 取消、重新安排和删除 |
| POST H/plan-items/{id}/restore-preview 或 restore | 预览与基于当前日计划修订恢复 |
| GET H/trash | 只返回当前有恢复权限且未到期的内容 |
| POST H/print-snapshots；GET H/print-snapshots/{id} | 创建／读取固定快照 |

列表以有界日期或游标读取。写操作沿用严格字段、同源与 CSRF、家庭归属、整数修订和幂等键；恢复预览只读，不需要幂等键。`today` 仍是 B1 日期入口，额外返回采购核对派生值；计划项增加场景、取消状态、具体内容标识／版本和选择时快照。

## 本轮证据与边界

见[验证报告](../output/b2-local-2026-10-31/report.md)。`npm run check` 覆盖原 B1 15 组与 B2 29 组，共 44 组真实 PostgreSQL／HTTP 测试；另有多身份真实 Chrome、28 个布局检查、2 份共 11 页 PDF 与独立数据库恢复证据。

测试全局只重建一次 5433 专用库；浏览器联调期间不运行重建测试。再次执行 `npm test`／`npm run check` 会使旧测试账号、快照链接及会话失效，测试夹具只供本机使用。开发库与测试库仍由连接地址、端口、用户名和库名共同防误连；Mailpit 只用于本机。

本轮工程功能在本机验证通过；完整 B2 家庭内容验收仍为部分通过。11 条真实菜谱和 2 张活动草稿继续待核对、不启用。真实手机／平板、实际打印机、生产邮件与部署、容量告警、七天家庭试用及 B3 的天气／自动计划／AI 未被本轮替代。B1／B2 本地 Git 基线随本次提交建立，保留已有用户改动；此前验证时的文件摘要清单继续作为历史证据。

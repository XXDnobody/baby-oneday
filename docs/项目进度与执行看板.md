## 5. 日常怎么管理

1. **一份看板作为进度入口。** 本文维护任务、状态和下一步；[产品需求](产品需求.md)管行为，[统一待定清单](需求对齐与待定事项.md)管决定和外部依赖，[验收映射](../specs/baby-plan/requirements.md)管覆盖。任务只引用原编号，避免复制整份需求。
2. **每次开工选一个可演示结果。** 同时最多推进两项：一项开发，一项内容或资源准备。新想法先进入候选队列，标明是否替换当前任务；明确的需求变更同步文档与验收。
3. **统一状态。** 待办 → 进行中 → 待验收 → 完成；遇到外部依赖可标“阻塞”，必须写明缺什么、由谁处理、何时复查。写完代码进入待验收，有执行证据后才完成。
4. **每次交付更新四项。** 完成了什么、如何验证、有什么阻塞、下一步是什么。功能任务记录代码版本与证据；原型验证和文档检查按各自范围标注。
5. **每周做一次真实演示。** 用手机和平板走当前里程碑流程，核对上周承诺、实际可用能力和剩余问题，再选下一轮目标。B4 的一周体验是额外的完整使用验收。
6. **多聊天共享编号。** 现有设计、需求等聊天作为专题上下文；后续任务引用 PM 编号和本地最新文档，完成后回写看板，避免结论只留在聊天里。需要跨聊天同时修改时先明确各自文件范围。

“完成”的共同标准：满足当前需求和权限规则；通过任务要求的正常、失败及边界用例；保存可复查证据并更新相关文档。功能集成验收还须证明真实接口、数据库和设备链路可用。

# 宝宝计划｜分享与家庭会员方案

版本：v0.4。日期：2026-10-30（Asia/Shanghai）。状态：与产品需求 v1.0、开发规格 v0.6 对齐。按家庭收费、先邀请试用、再以激活码交付的方向已确认；具体兑换与运营流程属于后续阶段设计，待定政策见[统一清单](需求对齐与待定事项.md)。当前仍是本地原型，尚未接入真实试用、订单、兑换、会员或公开分享服务。

首版已确定邮箱＋密码、首次验证邮箱、常用设备保持登录，忘记密码通过邮件重置；微信接入留待后续，不是当前前置条件。每位家人独立登录，手机、电脑和平板权限相同；记录的读写权限、AI 私有聊天规则沿用[开发规格](开发规格.md)，不会因购买会员扩大。

家庭照片上传和留存已退出当前需求。S1 自家计划和文字记录已确认使用期间保留、不按时间自动清理，删除后 30 天内可恢复；该决定不自动成为外部试用或付费会员的留存承诺。邮箱不可用时的人工恢复、会话工程参数、对外记录保存及到期政策仍需细化。S1 先完成自家使用，S2 再实现外部试用与权益，S3 实现收费，S4 实现公开分享与购买后直接开通。

## 1. 已确认的产品方向

- 对外销售「宝宝每日计划·家庭会员」，说明服务期限与权益，早期使用激活码交付。
- 一个家庭购买，成员分别登录，共享会员权益；邀请爸爸、妈妈、奶奶等家人不额外收费，业务操作仍由成员权限决定。
- 先让自家持续使用，再邀请 10～20 个外部家庭体验；首轮采用 7 天试用，观察完整一周后的持续使用，再开展付费测试。
- 初期只设一种付费会员，围绕个性化日常计划、AI 讨论与确认修改、家庭协作、平板使用、日历和文字与反馈记录提供服务。
- 试用邀请码、会员激活码、家庭邀请链接分别设计，购买或试用不会使用户加入其他家庭。
- 到期后保留已有安排和记录的查看、导出，停止新增付费服务；记录保存期限须提前明确。会员到期不自动删除家庭或成员关系。
- AI 用量设定明确额度，不承诺终身会员、无限 AI 或无限数据存储。
- 对外推广分享示例或经过预览的去身份信息内容；公开分享入口与家庭内部邀请分开。
- 正式公开销售量增加后，可改为购买成功直接开通；激活码继续支持赠送和渠道交付。

29 元／家庭／30 天仅为首轮测试报价示例，尚未成为正式售价。正式月费、年费、AI 额度及记录保存期限，需要结合使用反馈和成本确定。

## 2. 三类邀请与开通凭证

| 类型 | 谁发出、给谁使用 | 作用 | 关键规则 |
| --- | --- | --- | --- |
| 试用邀请码 | 运营方发给受邀家庭 | 为其自己的家庭开通 7 天试用 | 免费、单次兑换；码的最晚兑换日期与试用结束时间分开 |
| 会员激活码 | 运营方按已核实的订单或赠送记录发出 | 为指定家庭增加会员服务期限 | 一码兑换一次，绑定一个家庭；兑换前确认家庭、权益和生效后到期时间 |
| 家庭邀请链接 | 有成员管理权限的家人发给照护者 | 加入一个已经存在的家庭 | 免费、短有效期、可撤销；展示目标家庭和将获得的角色，不授予其他家庭的访问权限 |

实施建议：试用以家庭为单位只领取一次，换一个成员账号不能再次领取；已有付费权益的家庭不能用试用覆盖或降低原权益。家庭邀请建议一次接受后失效，邀请更多家人分别生成链接；具体有效时长待确定。

登录身份、家庭成员关系、会员权益分别保存。码和链接各自使用独立验证入口，误用时提示正确用途；任何一种会员凭证都不能替代家庭成员授权。

## 3. 用户流程

### 3.1 新家庭体验

受邀家庭查看介绍与示例 → 邮箱注册或登录 → 创建自己的家庭并完成必要设置 → 核对试用权益与期限 → 兑换试用码 → 使用 7 天 → 按实际阶段查看后续服务说明；付费入口在 S3 准备完成后开放。

阶段设计按成功兑换开始计时，设置过程不消耗试用期；外部注册准入细节在 S2 实现前确定。试用首日能形成一份实际可用的计划，随后可邀请家人参与。试用范围和条目适用月龄在开放前明确；首批围绕需求访谈时 17 个月宝宝整理的内容不能直接声明覆盖所有年龄。

### 3.2 购买与兑换

查看会员内容、价格、额度和保存政策 → 完成购买 → 收到激活码 → 登录并选择自己的家庭 → 预览权益及生效、到期时间 → 确认兑换 → 全家共享会员。

只有服务器确认成功后才显示开通。错误、已使用、已过期或已撤销的码有明确状态，错误提示不暴露其他购买者和家庭信息。建议由家庭主要维护者或明确授权的成员完成开通；付款和兑换不提升其照护操作权限。

首轮建议使用一次性购买的固定期限服务，不默认自动续费。具体收款渠道、订单核实方式、交付渠道和退款规则待支付方案确定后配置并展示，当前不建立实际销售或收款入口。

### 3.3 续费与到期

- 尚未到期时续费，从原到期时间继续累计；已经到期时，从本次成功开通时间起计算。
- 「30 天」作为固定天数套餐展示，不与自然月混称。后续如提供月费或年费，另行明确计时规则。
- 到期后能登录、查看已有安排和记录，并在预先告知的保存期限内导出数据；导出不要求先续费。保存期限、清理通知及记录导出方式必须在开放试用前确定。
- 新的 AI 调用、自动付费计划生成及其他新增付费服务停止，后台任务与接口执行同样检查权益；已保存安排不被清空。
- 到期后的免费新增或手动编辑能力尚未定义，不对外承诺永久免费的完整版本。
- 退款或撤销需对应原订单和权益记录，不能误撤销其他正常购买的服务；账号、家庭记录与成员关系继续按各自规则处理。

## 4. 会员权益与用量

| 范围 | 首期方向 | 开放前需要确定 |
| --- | --- | --- |
| 个性化日常计划 | 根据月龄、食材、天气和家庭习惯组织已核对的内容 | 内容适用年龄、生成频率及可用服务 |
| AI 助手 | 讨论、调整并预览改动，确认后保存 | 家庭共享额度、计量单位、重置周期、失败重试计量和额度用尽后的行为 |
| 家庭与设备 | 邮箱＋密码、首次验证邮箱、邮件重置、常用设备保持登录，手机、电脑和平板使用同一份家庭数据 | 邮箱不可用时的人工恢复、会话及邀请期限、发信投递与权限验证；微信留待后续 |
| 日历与文字反馈记录 | 保存按次文字与反馈记录，回顾及导出已有内容 | 记录保存期限、数据库备份和导出方式 |
| 服务期 | 7 天试用，随后测试固定期限付费 | 正式售价、续费方式、退款与支持规则 |

额度按家庭合计，不能因增加成员而自动增加多份额度。购买与兑换前应能看到适用的额度和政策版本；达到额度时先说明情况，不静默扣费。服务端按实际用量记录成本，不把重复打开页面等同于新的 AI 生成。

## 5. 对外分享

首期优先使用示例计划卡、一天陪玩安排或本周辅食示例介绍产品，点击后进入产品介绍与体验入口，由新用户创建自己的家庭。

用户主动分享真实计划时，先预览公开内容，默认去掉宝宝姓名、地点及其他家庭身份信息。公开内容使用单独生成的快照，只包含允许公开的字段，不把家庭内部日历、记录的内部访问链接放进分享页。共享快照不随私有计划修改自动更新；在线分享页应能撤销。

家庭内部「邀请家人」入口仅用于照护者加入，不承担公开推广功能。页面明确区分「邀请家人」和「分享给其他家庭体验」。

## 6. 运营后台与工程边界

S1 提供内容管理、任务与服务用量核查；S2 增加试用码的生成、期限配置、发放与兑换查询、家庭权益及到期处理；S3 增加会员激活码、订单关联、补发和退款后的权益处理。生成批次仅用于管理实际试用或销售，不对外制造未经确认的名额或销量。

工程实现建议：

1. 服务端校验登录者、目标家庭和兑换权限，不信任前端传入的会员状态、金额或期限。
2. 码使用不可预测的随机值，保存摘要用于校验；日志不记录完整码。补发未兑换的码时先使原码失效，已兑换的订单恢复原权益，避免重复开通。
3. 单次兑换和权益写入在同一事务内完成，配合唯一约束和幂等处理。同一码并发提交，只能有一个家庭成功；重试查询同一结果，不重复延长。
4. 对家庭的并发续费串行计算，起点为本次服务器时间与原有效到期时间中的较晚者。码的兑换截止时间与会员服务区间分别保存。
5. 订单、码和权益记录关联但状态分开。在线支付接入后只使用服务端验证的支付结果开通；人工交付阶段保留真实订单核实记录。
6. 家庭成员关系与会员权益分别校验。到期、退款、撤销不跳过家庭隔离，也不删掉其他有效订单对应的权益。
7. AI、计划生成及文字记录保存在服务端与后台任务中统一检查权限、权益和额度。具体计量及失败补偿规则在接入真实服务时确定。

这些是待实施方案，不能用原型按钮或浏览器本地存储代替正式校验。数据结构及工程阶段见[技术方案](技术方案.md)。

## 7. 分阶段实施

| 阶段 | 本阶段交付 | 判断依据 |
| --- | --- | --- |
| S1 自家可用 | 真实账号、家庭邀请与隔离、日常安排、AI、天气、文字记录、回收站、多端使用、打印及备份恢复 | 家人连续一周使用，覆盖工作日和周末；核心保存、权限、同步、删除恢复及数据库恢复验证通过 |
| S2 外部试用 | 邀请 10～20 个家庭；7 天试用、家庭权益、用量记录、到期查看与导出 | 一周后是否仍主动使用，是否有多位照护者参与，实际成本和支持负担 |
| S3 收费测试 | 一种会员、真实订单与激活码、续费和退款处理 | 试用转付费、持续使用、服务到期后的实际续费及退款原因 |
| S4 公开推广 | 产品介绍、可预览及撤销的分享快照、购买成功直接开通 | 在已有使用与付费数据支持下扩大覆盖 |

统计以家庭为单位，记录邀请、兑换、形成首份计划、实际使用、付费和续费等行为；浏览量和发码量不能单独证明产品有用。量化成功门槛在取得首轮数据后制定，不把尚未发生的购买或续费记为验证结果。

## 8. 验收场景

保留 MB 编号作为验收设计。MB-08 属于 S1 家庭邀请验证；试用、权益与额度场景在 S2 执行，会员订单、续费、退款场景在 S3 执行，公开分享 MB-10 在 S4 执行。以下均不表示已完成真实服务测试。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| MB-01 | 同一家庭的父母与奶奶登录 | 共用会员，仍分别执行成员权限；加入家人不另收费 |
| MB-02 | 在错误入口输入另一种码 | 不开通错误权益、不加入错误家庭；提示用途且不泄露家庭信息 |
| MB-03 | 两个家庭同时兑换同一码 | 最多一个成功，另一方不获得权益；网络重试不重复开通 |
| MB-04 | 兑换码截止日期与服务期不同 | 页面分别展示；服务期限按成功开通或续费规则计算 |
| MB-05 | 提前续费及过期后再开通 | 分别从原到期时间和新开通时间计算，没有天数丢失或重复累计 |
| MB-06 | 同一家庭换成员再次领取试用 | 不重置试用；试用也不能覆盖付费权益 |
| MB-07 | 试用或会员到期 | 停止新增付费服务，后台任务同样生效；已有内容按告知期限可查看和导出 |
| MB-08 | 家庭邀请撤销或链接过期 | 不能加入，已登录者也不能绕过检查取得家庭数据 |
| MB-09 | 退款、撤销或补发 | 对应到原订单，不重复开通，不删除家庭记录或误撤其他有效权益 |
| MB-10 | 对外分享计划 | 可预览公开快照；不包含家庭私有入口、私有记录链接或默认排除的身份信息 |
| MB-11 | 额度耗尽或并发使用 | 服务端按家庭共享额度处理，给出明确提示；不静默超额扣费 |

## 9. 仍需验证

待定项与最晚处理时间以[需求对齐与待定事项](需求对齐与待定事项.md) Q-06～Q-08 为准；登录与存储等基础条件同时沿用其中的 S1 清单。

- 测试报价：29 元／家庭／30 天，仅为假设；正式月费、年费待成本和付费结果支持。
- AI 额度与记录保存期限，以及额度耗尽、到期后的具体功能边界。
- 适用月龄、账号恢复与会话期限、家庭邀请有效时长、收款与交付方式、退款及支持规则。
- 真实家庭的持续使用、维护成本和公开服务容量；不依据现有服务器套餐直接承诺家庭数量。

商业方向来源于本次用户确认。外部产品仅作为结构参考：[Huckleberry 会员页](https://huckleberrycare.com/pricing) 将基础记录、多设备同步与个性化计划、AI 等权益分层；该参考不能证明本产品的定价或用户付费意愿。

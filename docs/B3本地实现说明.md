# B3 本地实现

日期：2026-10-31（Asia/Shanghai）。版本标记：`local-b3-2026-10-31`。继续使用 Next.js 16.4.3、TypeScript、真实 PostgreSQL、Mailpit 与 A 版界面，复用家庭授权、锁、事务、修订、内容适用性、回收站、幂等及共享同步。只新增迁移 `005_b3.sql`，未修改 001～004。

## 天气与穿搭

管理员在“我的家庭”确认实际城市、经纬度与坐标来源；所有成员可按日期和活动时段刷新天气。使用家人提供的坐标，不调用或存储 GeoAPI 城市结果。当前天气、逐小时预报、有效时段、取数时间、来源与状态分开保存并展示。完整覆盖所选时段且未过时的小时预报才用于穿搭；缺失、过时、超时、限频和异常明确降级，当前天气不会冒充未来预报。

衣物类别参考有规则版本、温度与风雨条件、天气快照标识及解释，明确未做专业审核。天气变化由家人决定是否调整活动，刷新不会自动替换已选内容。普通天气正文按本地 24 小时策略清理，过期读取即时限制；最小溯源保留。官方依据、缺项和真实接入边界见[服务核查](B3服务接入核查.md)。

## 次日自动计划

首次完成初始化持久化准备今天的任务。夜间自动设置默认关闭，仅管理员修改；20:00 是集中工程默认建议。启用后 worker 按家庭时区准备次日，早上重启会补偿今天；周六、周日使用周末模板。作息可明确时段类型和场景，旧模板按名称保守分类，普通成员仍可维护。

任务与租约存在 PostgreSQL，`household + date` 为持久业务唯一键；任务领取采用行锁、租约和执行栅栏，进程中断后可恢复，普通失败有有界重试，终态失败可显式重试。已成功的同日任务不会因换请求键再生成。任务和正式改动在同一事务完成。

按目标日期复用月龄、已核对食物资料、启用版本、期限偏好及场景校验，库存只排序、不扣减。户外内容没有可用时段天气或预报风雨时待家人核对。没有候选保存“饮食待安排／活动待安排”并说明原因，不启用 11 条菜谱或 2 张活动草稿，也不补造核对事实。

同一时段已有条目或持久保护标记时跳过。人工保存、明确待安排／留空、取消、删除和已确认 AI 结果都会留下保护标记；手动调整自动条目也转为人工保护，原时段标记保留，正文清理不移除标记。模板变化不重写既有计划。

## 私有 AI 讨论与一次确认

“AI 助手”显示具体宝宝与固定的开始／结束日期，每次最多 31 天，可跨多日。会话、消息、预览和任务结果仅发起人可读，管理员无隐含权限；普通任务列表及家庭 SSE 不包含 AI 私有结果。

授权上下文只含当前可读资料、目标日期的有效偏好、适用的启用内容、未删除的计划与记录、可用天气，以及本人消息。删除、过期、不适用内容与他人私有聊天被排除。依据变化后，旧助手消息不再进入模型上下文。输入有大小上限，超出时要求缩小范围。

查询直接回复。写入先产生严格结构和服务器生成的真实前后值预览；聊天不改正式资源。首版白名单：新增／调整日计划，确认食材快照，新增／提前结束期限偏好，更新工作日／周末模板。禁止 SQL、账号、成员、付费、记录删除、宝宝关键资料、禁忌、自动设置及内容启用操作。2026-10-31 根据实际使用修正：饮食和活动既可引用经校验的内容版本，也可使用明确标为 AI 生成的单次结构化建议；不具备必要条件时仍可保留待安排。新建议确认后只保存本次安排，不自动加入或启用内容库；自动任务继续限定已启用内容。库存未知列采购，户外建议须有出门条件和室内备选。

继续发送消息立即替代待确认预览，即使新轮仅查询或失败，也不能确认旧版。确认限定本人，重新授权并检查完整依赖摘要、内容状态、会话版本和预览期限（工程默认 15 分钟）。偏好与计划组合按整组最终状态检查。所有正式写入、修订、审计、共享资源事件和执行事实一次事务提交；后项失败全组回滚。外部模型调用及用量账本不放进业务事务。

`proposal_executions.proposal_id` 永久唯一，成功响应丢失、重复确认或换幂等键均返回同一执行事实。正式资源通知不包含聊天、预览、方案标识或私有文本。模型或天气不可用时手动安排与既有资料仍可使用。

## 本机运行与验证顺序

```sh
npm run env:up:test
npm run db:migrate
npm run env:services
npm run dev
```

另开进程执行 `npm run worker`。单轮维护可用 `npm run worker:once`；测试环境明确追加 `-- --test`。本机主入口为 http://127.0.0.1:3000，邮件为 http://127.0.0.1:8025。家庭页维护地点、自动计划和作息；每日安排查看天气、准备次日；AI 入口查看本人讨论与最终预览。

`npm run check` 先做类型、lint、重建专用 5433 测试库并运行接口测试，最后构建。浏览器联调必须随后运行，不能在联调时再次重建库。`npm run dev:test:b3` 只连接测试库，并启动明确标记的 loopback 天气／模型和测试 worker；它不代表真实服务接入，不能用于开发库或部署。

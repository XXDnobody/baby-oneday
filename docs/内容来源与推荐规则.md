# 宝宝计划｜内容来源与推荐规则

版本：v0.4。更新：2026-10-30（Asia/Shanghai）。状态：与产品需求 v1.0 对齐，补充草稿、核对、家庭启用及新版本的使用边界；来源选择方向、推荐依据和解释方式已确认，具体条目、天气服务及页面仍需整理、接入和验证。本次未重新审阅外部资料或完成内容审核。

本文件记录饮食、活动、天气与穿搭讨论的确认结果。首批内容围绕 2026-10-28 需求访谈时 17 个月宝宝的家庭使用整理，正式筛选使用实际月龄依据；外部试用的年龄范围另行确定。认可来源方向不等于所有引用该来源的菜谱、活动或穿搭组合已经核对或适用于宝宝。内容核对及服务接入待办见[统一清单](需求对齐与待定事项.md) C-01、E-04；内容启用范围已确认仅管理员可修改；妈妈、奶奶仍可选择已启用内容。活动卡以图文为主，英语音频按核心需要补充，视频后置。家庭照片功能取消不影响内容说明配图。

## 1. 已确认的共同原则

- 每条推荐回答“依据是什么”和“为什么今天选它”。可核对资料支持一般原则，家庭资料与当天条件支持具体选择，AI 负责筛选、整理、改编和解释。
- 区分指南原则、具体做法来源、家庭经验和当天选择理由。一般指南支持某项原则，不代表指南直接推荐了系统组合出的整道菜或整个活动。
- 保留出处对应的具体章节或段落、版本或日期、适用条件，以及本产品如何使用该资料。原文摘要与本地改编分别标注。
- 家庭确认、出处及适用条件核对、专业人员审核分别记录。界面只展示实际完成的核对或审核状态。
- 日常自动安排使用家庭已启用且符合适用条件的内容；现有 AI 方案预览与确认规则继续适用。资料更新保留版本，历史安排和记录能够找回当时的内容。
- 原型示例、家庭真实记录和正式服务数据分别标注。资料缺失时保持未知，不由 AI 补写成已经确认的事实。

内容使用状态按产品需求 §5.1：原始草稿保留供核对；核对完成后供管理员审阅；家庭启用且符合当前条件才可进入选择与自动安排；停用或待重新核对的版本不再用于新安排。来源核对、专业审核和家庭启用分别保存；原料或做法新版本不能静默继承旧版全部审核结论。已排入的未来内容如不再适用，提示处理；历史仍保存原版本。

首批 11 条家庭菜谱全部保留为未启用草稿。核查出的用量、步骤与映射缺项继续处理，不由模型补造事实；只有旧月龄默认值、名称匹配或旧食材“通过”不满足当前适用性确认。没有合适内容时留待安排，不以未经核对的生成内容补齐菜单。

## 2. 饮食的来源与推荐规则

### 2.1 营养原则的资料起点

| 资料 | 版本或日期 | 采用用途 |
| --- | --- | --- |
| [中国营养学会：《中国婴幼儿喂养指南（2022）》核心信息](https://dg.cnsoc.org/article/04/gc5cUak3RhSGheqSaRljnA.html) | 2022；其中 7～24 月龄部分覆盖当前月龄 | 建立食物多样化、动物性食物、添加糖盐、顺应喂养及进食安全等基础原则 |
| [国家卫健委：《婴幼儿营养喂养评估服务指南（试行）》](https://www.nhc.gov.cn/fys/c100078/202502/19903ff647694f3a85ed6fe332380b34.shtml) | 2024 年印发，2025 年公开 | 将食物种类、喂养行为和生长情况一起纳入内容适用性判断的参考 |
| [WHO：6—23 月龄婴幼儿辅食喂养指南](https://www.who.int/publications/i/item/9789240081864) | 2023 | 补充与交叉核对，保留具体建议的年龄和其他适用条件 |

以上为已确认的资料选择方向。进入可用内容库前，仍须核对支持具体结论的原文；不同资料的条件或结论不一致时，记录差异与采用理由。

### 2.2 具体菜谱的整理来源

1. 优先整理家里已经会做、宝宝接受的菜，保留家庭实际做法，标明“家庭菜谱”。
2. 检查旧辅食小程序能够导出且可核实的条目，再决定复用；旧系统生成过不等于家庭实际做过或已经核对。
3. 从医疗机构、营养专业机构公开的食谱和做法补充，按条目核对出处、步骤和适用条件。

每份菜谱至少保存名称、原料、参考份量及其依据、软硬与切配要求、步骤、适用条件和做法来源。家庭修改单独保留；参考份量不等于宝宝实际摄入量。尚未填写或核对的字段保持待补充。

### 2.3 当天排餐依据

推荐顺序为：

1. 核对已知过敏或禁忌、当前进食能力和食物处理方式，过滤不适用候选。
2. 连同其他餐次和奶类安排检查全天搭配，避免仅凭一道菜判断全天营养。
3. 在合适候选中优先使用已确认的现有食材和优先消耗项。
4. 结合近期接受程度、照护者时间、准备难度和菜单变化排序。

食物禁忌、近期偏好、库存状态分别保存。“最近不爱吃面”不能转换成过敏或永久禁食。库存确认时间和粗略余量用于排餐与采购核对，不据此自动判断食材新鲜度。

推荐理由分别引用实际用到的内容版本、家庭食材快照与偏好记录。信息不足时不宣称“营养全面”“补铁充足”，也不生成没有计算依据的营养数值。

### 2.4 原型示例的处理

“蒸南瓜＋原味酸奶”“番茄鸡蛋面”等目前仍是原型示例。整理成正式条目时补齐适用条件、份量依据和做法来源，并核对当天安排。

解释示例（假设两种食物已确认适用，库存状态如原型所示）：

> 家里有优先吃的南瓜，这份加餐准备步骤较少；酸奶需要先核对库存，并结合当天奶类安排决定。

这段话中的库存和安排理由属于家庭与系统层面的依据，不能标成指南直接推荐的组合。

## 3. 活动的来源与推荐规则

### 3.1 资料起点

| 资料 | 采用用途 |
| --- | --- |
| [国家卫健委：《婴幼儿早期发展服务指南（试行）》](https://www.nhc.gov.cn/fys/c100078/202502/19c9c6dee0274d23822f313a99ae1779.shtml)及[《婴幼儿亲子交流与玩耍要点》](https://www.nhc.gov.cn/fys/c100078/202502/19c9c6dee0274d23822f313a99ae1779/files/1741749469666_88130.pdf) | 2024 年印发、2025 年公开；建立分月龄的交流和玩耍参考，首批重点核对覆盖当前月龄的部分 |
| [WHO：Improving early childhood development](https://www.who.int/publications/i/item/97892400020986) | 2020；采用回应性照护与早期学习的总体原则 |
| [UNICEF：21 learning activities for babies and toddlers](https://www.unicef.org/parenting/child-care/21-learning-activities-babies-and-toddlers) | 整理散步、指物命名、假装游戏、放入与取出等具体玩法；按实际能力调整 |

家中育儿书作为补充候选资料，核对实际章节后才能引用。仅识别封面不能标成已经审阅。

### 3.2 具体活动与当天筛选

每张活动卡保存材料、场地、步骤、目的、观察点、简化或变化方式、适用条件和来源。目的与观察点需符合资料实际支持的范围。

月龄用于初步筛选，同时结合家人已记录的实际能力、近期兴趣、当天照护者、场地、材料、天气及疲倦等状态选择。未记录的能力或兴趣保持未知；单次没兴趣不形成长期能力判断。

允许重复熟悉的活动，再逐渐增加变化；不要求每日全新，也不以必须完成的数量或回答正确率评价宝宝。时长按当天情况调整，固定训练分钟数尚未作为家庭要求。

### 3.3 “找一找秋天的颜色”的出处表达

该活动可参考 UNICEF 的陪伴散步与回应指向、命名物品等玩法，结合季节环境改编。原型中的整套活动尚须逐条核对后才能启用。

- 目的：在散步中创造共同观察和来回交流的机会。
- 做法：跟随宝宝停留或指向，用一句短话描述，再等待回应。
- 观察：是否愿意停留、指向、模仿声音或继续交流。
- 调整：兴趣变化时跟随新的关注点，累了就结束。
- 出处标记：显示具体参考段落及本地改编说明；“秋天的颜色”作为主题，不设必须说对颜色名称的要求。

## 4. 天气数据的来源与城市处理

和风天气 API 为首版优先接入候选。已核对公开接口能力；账号、额度、费用、服务器访问情况和当地预报表现仍需实际验证，当前没有完成服务接入。

资料起点：[实时天气](https://dev.qweather.com/docs/api/weather/weather-current/)、[逐小时预报](https://dev.qweather.com/docs/api/weather/weather-hourly-forecast/)、[来源标注要求](https://dev.qweather.com/en/docs/terms/attribution/)。

已确认的使用规则：

- 家庭选择省、市、区县，必要时选择外出地点，再匹配服务商查询位置；不同城市或地点的数据分别获取。
- 当前天气用于说明现在；某次外出采用覆盖实际活动时段的逐小时预报。全天高低温作为概览。
- 推荐考虑可获得的气温、体感温度、风速及阵风、降水、湿度和紫外线等数据；缺失字段不能假定为没有风、没有雨或没有风险。
- 页面显示地点、数据类型、预报对应时段、来源和最近取数时间；接口提供的数据时间与取数时间分别保存。没有提供的发布时间或观测时间不由系统编造。
- 切换地点后查询新地点；获取失败、过期或离线时显示真实状态，不把旧地点或过时数据当作当前依据。
- 按供应商要求展示归因，保留接口提供的必要来源信息；缓存、保存期限和历史天气留存按服务条款与实际数据产品确定。

天气更新可以刷新事实与穿搭建议，不能自动替换已经选定的活动；调整活动需沿用成员权限，通过明确操作或 AI 方案预览确认。

## 5. 穿搭的来源与场景理由

原则来源为美国儿科学会面向家长的[寒冷天气穿衣资料](https://www.healthychildren.org/English/safety-prevention/at-play/Pages/Cold-Weather-Safety.aspx)与[炎热天气照护资料](https://www.healthychildren.org/English/safety-prevention/at-home/Pages/Protecting-Children-from-Extreme-Heat-Information-for-Parents.aspx)。从原文核对分层调节、保持衣物适宜、避免过热等适用原则。

具体衣物组合是系统结合活动和天气推导的场景建议，标明依据，不宣称某个温度存在适用于所有宝宝的固定穿衣件数。首版继续推荐衣物类型与组合，尚不涉及衣橱照片或逐件衣物搭配。

| 活动场景 | 推荐时需要解释的因素 |
| --- | --- |
| 持续走动或活动 | 活动量、透气和行动便利、外层是否容易脱穿 |
| 坐推车或被抱着 | 自身活动量较少，结合风和体感选择可加减外层 |
| 秋千或风口停留 | 风、停留方式、坐下后裤脚是否上移；必要时先调整场地 |
| 活动后进入室内 | 实际室内条件、出汗和衣物是否潮湿，重新调整；不能用室外气温代替室温 |

“坐秋千时检查裤脚”作为具体舒适与暴露情况的检查提醒。用户观察到露脚踝后流鼻涕的先后关系，保留为家庭观察，不记录成已经证实的疾病原因或预防效果。[感冒病因参考：CDC](https://www.cdc.gov/common-cold/about/index.html)。

家庭后续反馈可用于调整推荐，并保留时间、活动及当时条件；一次反应不固化为“宝宝一直怕冷”等长期结论。

## 6. 推荐解释与来源展示

展示分为三个层次，具体入口布局仍为待验证的交互设计：

| 层次 | 内容 |
| --- | --- |
| 先看怎么做 | 一句餐食、玩法或出门准备建议 |
| 再看今天为什么 | 简短解释真正影响选择的食材、偏好、场景、记录或天气条件 |
| 展开查看依据 | 资料标题、机构或作者、原始链接、版本或日期、具体章节或段落、适用条件、原文摘要或改编说明、真实核对或审核状态 |

一般原则与当天理由分别关联依据。家庭事实关联实际记录及日期；天气关联地点、数据类型、有效时段和取数时间。引用应随内容整理和选择保留，不在事后由 AI 补上看似相关的链接。

资料核对、家庭启用和专业审核是不同状态。没有专业审核时如实展示，家庭认可不能转换成专业背书。

## 7. 后续整理与接入任务

- [ ] 为首批资料建立来源记录，定位具体章节或段落，记录适用条件及支持的结论。
- [ ] 整理家庭常做菜谱；截至 2026-10-30，用户已确认将所选 4 人家庭的全部 11 条个人菜谱草稿纳入首批。[首批清单](首批资料复用清单.md)已保留原料、用量、51 条步骤与原提示，逐项标出名称映射和做法缺口。继续核对实际用料、来源及适用条件；“无糖厚酸奶”的旧含糖标签冲突、馄饨缺少煮制步骤等均保持待处理，不把默认月龄、标签或已有原料标识视为已审核。系统菜谱另见[核查报告 v0.4](旧小程序资料复用核查.md)。
- [ ] 围绕当前月龄整理户外、室内及日常互动活动卡，保留改编说明。
- [ ] 整理穿搭规则的适用条件与场景理由；具体温度分段和规则参数待核对、实现及家庭试用。
- [ ] 验证和风天气账号、额度、费用、访问情况、字段与归因，接入城市或地点及时段查询。
- [ ] 在原型和正式应用中落实推荐理由、来源详情和数据状态；当前原型的菜谱、活动及 21°C 天气继续按示例处理。
- [ ] 使用真实家庭反馈检查内容是否易做、解释是否可信、来源是否能核对及维护负担是否合适。

## 8. 验收补充

1. 一般指南与家庭自定义菜谱同时使用时，能分清原则依据、做法来源和当天选择理由。
2. 每个改编活动能找到具体参考位置与改动说明；单个通用机构链接不能替代条目核对。
3. 每条个性化理由都能对应实际输入，缺少记录时不声称“宝宝喜欢”或“家里有”。
4. 更换城市、活动时间或活动方式时，重新核对受影响的天气和穿搭；无法取得有效数据时明确降级。
5. 出处核对、家庭启用、专业审核的界面状态与实际记录一致。
6. 更新资料、内容或推荐规则后，历史安排仍能查看当时采用的版本与依据；天气留存遵循所选服务的数据使用条件。

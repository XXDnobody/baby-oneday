# 单人开发流程与 Skill 使用

整理日期：2026-10-31 · Skill：`solo-dev-workflow` · 工作流版本：1.0

把已讨论的单人开发方式保存为可复用 Skill。默认完成用户已经要求且已授权的工作；小改动自动缩短流程。源码入口见 [SKILL.md](../../../output/skills/solo-dev-workflow/SKILL.md)。

## 1. 每次如何开始

```text
使用 $solo-dev-workflow，完成这个新需求：
{{用户是谁、希望做什么、必须遵守哪些已知规则}}
```

直接描述目标即可。Skill 会先读取当前项目已有资料，补充必要验收与任务，再实现和验证。关键业务条件缺失时只处理相关问题，不要求你逐阶段审批。

只需要方案：

```text
使用 $solo-dev-workflow，只梳理这个需求的方案和验收条件，暂不改代码：
{{需求描述}}
```

继续上次需求：

```text
使用 $solo-dev-workflow，继续 {{需求名或功能记录路径}}，
从未完成的验收项和任务接着做。
```

## 2. 六步流程

| 步骤 | 实际工作 | 最小记录 |
| --- | --- | --- |
| 读取现状 | 项目约定、已有需求、相关代码、版本和未提交改动 | 有效入口与代码起点 |
| 明确验收 | 用户目标、范围、正常结果与适用反例 | AC-01 等验收项 |
| 确定方案 | 最小改动位置、必要契约或迁移、任务顺序 | 几句话方案与任务清单 |
| 实现 | 按范围修改，选择必要验证，保护已有工作 | 当前动作与对应 AC |
| 验证 | 执行适当检查、修复失败、完成相关回归 | 真实版本、环境、结果与证据 |
| 交付 | 检查差异、同步文档、落实所要求交付 | 完成内容、限制、下一步 |

```mermaid
flowchart LR
    A[读取现状] --> B[明确验收]
    B --> C[确定方案]
    C --> D[实现]
    D --> E[验证]
    E -->|失败| D
    E -->|通过| F[更新记录与交付]
```

仅做方案时完成相应阶段；已经授权的发布需求还包括部署与发布后检查。存在受阻项时，先完成能独立完成的工作，再记录其具体影响。

## 3. 三种深度

- **快速**：局部文案或样式等低影响可逆改动，通常在现有任务记录结果，无需新建功能单。
- **标准**：功能或行为变化，通常只维护一张功能单；已有规格与任务足够则直接复用。
- **扩展**：权限、数据隔离、收费、迁移、并发写入、外部副作用或产品内 LLM 行为，在标准流程上增加相关检查。

改动文件数量不决定风险。小型权限改动仍需要权限与数据反例；没有模型运行时行为的普通编码任务不添加模型评测。

## 4. 每个需求留下什么

一个集中入口应能回答：

- 要实现什么、哪些不属于本次。
- 每个适用验收项如何检查，实际检查结果是什么。
- 改了哪里，哪些文档和契约是权威定义。
- 哪些已完成、未完成、未验证或受阻。
- 下一次从哪里继续，哪些已有修改需要保留。

功能单中引用已有接口、迁移、测试文件和证据，不复制第二套字段定义，不额外生成独立追踪矩阵、正式评审报告和每日进度表。

## 5. 对“宝宝计划”的适配

Skill 内有按需读取的项目入口导航，复用现有产品需求、开发规格、冻结基线、任务和测试资料。它不把某次聊天的阶段、账号条件或测试结果当成永久事实。

家庭权限、个人私有内容、并发修改、删除恢复及 AI 方案执行等，根据本次需求和当前有效契约选择检查。命令从当前 package.json 和开发指南发现，不将旧命令硬编码为所有需求必跑步骤。

## 6. Skill 的文件与使用范围

```text
solo-dev-workflow/
├── SKILL.md
├── agents/openai.yaml
├── assets/feature.md
└── references/
    ├── extended-changes.md
    └── baby-plan.md
```

Skill 本身是指令与模板，执行时由编码代理调用当前环境的工具。日常使用不依赖额外 Python 包或某个插件。

创建时保留正常自动选择；显式指定 `$solo-dev-workflow` 可明确使用本流程。当前机器沿用已在使用的个人 Skill 目录 `~/.codex/skills/solo-dev-workflow`，供不同项目调用。

按 [官方 Skill 文档](https://developers.openai.com/codex/build-skills)，Codex 会自动检测 Skill 变化；列表未刷新时可重启。对外分发可以使用单独的 Skill 压缩包，不需要复制整个“宝宝计划”仓库。

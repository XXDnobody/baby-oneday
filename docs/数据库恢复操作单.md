# 数据库恢复操作单

日期：2026-10-31（Asia/Shanghai）。本轮只验证本机 5433 的隔离恢复；**没有生产备份周期、容量、异地留存、RPO／RTO 或生产开放结论**。回收站的 30 天不等于备份保留期。

## 已验证的两种核对

1. 一致性快照：在源测试库的 repeatable-read 事务导出 PostgreSQL snapshot，用同一 snapshot 做 `pg_dump -Fc`。恢复到独立 `baby_plan_restore_*` 库，逐表比较行数和逐行内容摘要，涵盖计划、历史、记录、作者、AI 归属／执行事实和任务。
2. 恢复点之后的控制变化：先备份，再实际删除／恢复／撤销，并模拟服务端到期和凭证变化；导出无正文的签名核对资料，向恢复副本重新施加删除、撤销和执行暂停。缺失版本与写入列为 `dataGaps`，不自动宣称可开放。

完整检查包含 `tests/recovery.test.ts`。结果在[恢复演练](../output/b4-local-2026-10-31/recovery-drill.json)；旧 B3 的 38 表证据仍保留。本轮恢复副本检查后移除，dump 和核对资料仅保存在受忽略的 `.local/backups`、`.local/recovery`，不提交或展示令牌／正文。

## 本机重跑完整故障演练

先停止 **3001 测试 Web 和测试 worker**，确认没有连接这些夹具的浏览器会话。以下测试会重建 5433 的业务数据，不能在联调期间运行：

```sh
BP_EVIDENCE_DIR=output/b4-local-2026-10-31 npm run check
```

仅重跑恢复故障测试也会触发相同测试库初始化，仍须先停止测试应用：

```sh
npx vitest run tests/recovery.test.ts
```

普通快照一致性复验不重建源库：

```sh
npm run db:verify-backup -- --output=output/b4-local-2026-10-31/backup-verification.json
```

测试过程自动创建并移除恢复库。主测试库固定为 loopback 5433、用户／库名 `baby_plan_test`；恢复工具额外拒绝开发库、主测试库及任何不符合 `baby_plan_restore_*` 的目标名。没有应用开放或生产发布命令。

## 有保留副本时的控制核对步骤

1. 保持副本与 Web／worker 隔离；选择经过快照完整性检查的 dump，登记备份点、数据库来源标识、迁移清单及恢复目标。不要替换开发库或让普通应用连接副本。
2. 停止源 Web 与所有 worker，确认最后业务写入已结束。若最新源库、连续删除／撤销流水或最后写入无法确认，**停止开放流程，保留隔离**。旧检查点即使签名正确也不能证明最后写入完整。
3. 对停止写入的源测试库导出核对资料。文件只有对象标识／修订、删除及截止时间、权限／凭证版本、无正文控制流水及数据摘要；没有邮箱、密码、令牌或 AI 聊天。

```sh
npm run recovery:checkpoint -- --test --output=.local/recovery/latest-checkpoint.json
```

4. 向已准备的独立恢复库施加控制，目标名用实际已核实的库名替换下例。`--confirm-source-frozen` 是操作者对已完成第 2 步的确认，工具不会替你停止进程，也不能用此参数掩盖未知流水。

```sh
npm run recovery:reconcile -- --test \
  --database=baby_plan_restore_manual_b4 \
  --checkpoint=.local/recovery/latest-checkpoint.json \
  --confirm-source-frozen \
  --output=output/b4-local-2026-10-31/reconciliation.json
```

核对文件使用本环境 `AUTH_SECRET` 做 HMAC；不会输出密钥。来源标识、迁移名／校验和、严格结构及签名必须匹配。文件有效性本地默认 5 分钟，过期须在源库仍冻结时重新导出；这是防误用工程参数，不代表已确认的生产恢复指标。不要替换或丢失环境密钥后仍声称能验证旧检查点。

5. 查看报告。工具的 `openToUsers` 始终为 `false`；完成限制施加不等于业务数据补齐。`dataGaps` 中的缺失／不同版本须逐项用有效源数据、历史和执行事实核对；不能靠删除差异清单“通过”。
6. 复验保留记录的原作者／发生日期／独立快照，核对当前授权、旧会话失效和私有 AI 归属；所有后续开放决定另行评审。本轮没有执行任何生产开放。

## 工具的实际处理

| 情况 | 已实现处理 |
| --- | --- |
| 备份后删除 | 使用最新删除时间和截止时间施加 tombstone，保留原对象标识；不会重新算 30 天 |
| 截止已过、或源库已清理正文 | 副本清除正文、旧版本、相关旧打印正文与幂等正文；有效记录自己的当时计划快照保留 |
| 备份后恢复 | 不凭控制流水补造正文或修订。与备份不一致的活动记录和历史版本进入 `dataGaps`；仍保持隔离，旧删除状态不自动转成可见 |
| 成员被撤销／降级 | 在副本重新撤销／降级；不把旧备份的管理权限复活；不会自动提升、重新加入或新建成员 |
| 凭证版本变化 | 旧密码不能继续作为有效凭证：副本账号保持停用，列明需处理。不得擅自重置家庭密码；优先取得最新完整备份或由操作者另行核实账号恢复方式 |
| 会话和未用准入凭证 | 所有旧设备会话撤销；未用邀请、验证／重置票据失效，未消费初始化令牌失效；之后须重新验证／邀请 |
| AI 与任务 | 私有会话／作者归属和唯一执行事实保留；待确认方案失效，未完成租约与任务暂停，自动设置关闭；禁止自动重放旧方案 |
| 保护标记 | 合并最新人工／删除时段保护，防止恢复后自动任务补回已移除时段 |
| 天气 | 超过正文保留期限的数据清除；读取仍按当前有效期降级，不把备份天气当新预报 |
| 中途失败 | 事务回滚，不留下半份删除或权限状态。缺资料、篡改、过期、错误来源、迁移不一致或误指主库均拒绝 |

## 生产仍需落实

外置且连续的删除／撤销控制流水、最后写入证明、受控备份账户、加密及密钥管理、备份容量／周期／保留与清理、异地恢复、监控告警、可接受丢失窗口、实际恢复耗时、账号与成员重新授权流程，以及经验证的部署／回退步骤。当前本机检查点与 dump 在同一电脑，不能算异地灾备；主机与日志都丢失时没有依据证明恢复点后状态完整，副本继续隔离。

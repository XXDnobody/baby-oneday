# 宝宝计划｜页面结构与核心交互

版本：v0.11。日期：2026-10-30（Asia/Shanghai）。状态：与产品需求 v1.0、开发规格 v0.6 对齐，沿用 A「日常工作台」。[A 版扩展原型](../web-ui/extension-overview.html) 已提供核心本机演示；邮箱注册与找回、初始化、来源详情、回收站和新版权限仍需补齐页面及真实服务。待定事项见[统一清单](需求对齐与待定事项.md)，历史演示不作为权限与保存政策的依据。

## 1. 三种使用场景

| 场景 | 使用者与设备 | 核心任务 |
| --- | --- | --- |
| 管理、记录和回顾 | 你与宝宝妈妈，手机或电脑 | 与 AI 讨论安排、确认改动、查看日历、换餐换活动、随手记录与回顾 |
| 查看和日常操作 | 平板，横屏或竖屏 | 看清当前与下一项、菜谱、穿搭和提醒，直接查日历、记一下，按成员权限调整计划 |
| 做饭与线下查看 | 奶奶，平板或打印页 | 直接看到原料和做法，按需要带着纸张执行；其他日常操作按编辑成员权限提供 |

手机优先提供简短操作入口。电脑使用相同信息结构，适合整理模板和内容。平板直接登录成员账号，进入适合触屏和大字阅读的平板模式，也能使用普通视图；权限和数据与手机、电脑一致。

## 2. 页面与导航建议

新增需求后，手机底部导航建议采用“今天、日历、饮食、活动、家庭”五个入口；电脑侧栏按相同结构增加“日历”。天气穿搭属于“今天”的重点卡片；平板模式是同一系统的大字触屏布局入口。

AI 在各管理页顶栏有固定“AI 助手”入口，今日页增加一条醒目的对话入口。它打开同一套会话功能：电脑用右侧面板，手机用完整对话页并保留返回位置。A 版扩展原型已提供相应本机演示，实际设备与家庭使用效果仍需验证。

| 页面 | 路由建议 | 主要内容 |
| --- | --- | --- |
| 产品介绍与示例 | `/welcome` | S2 向受邀家庭说明试用、展示示例；S4 扩展公开推广，不包含家庭内部资料 |
| 登录 | `/login` | 邮箱、密码、保持登录选择、忘记密码；允许密码管理器填充，显示统一登录失败提示 |
| 邮箱验证与受邀注册 | `/register` | 从有效邀请或受控初始化进入，填邮箱、收验证码、验证后设置密码及称呼；发送冷却、改填邮箱、验证码失效和邀请失效均有处理 |

| 回收站 | `/family/trash` | S1 提供可恢复的计划条目与本人有权恢复的文字记录、删除时间、恢复截止时刻、恢复预览及结果 |
| 穿搭详情 | `/today/clothing` | 按活动场景组织的衣物组合、天气依据和出门检查 |

| 活动详情 | `/activities/:id` | 简短玩法、材料与步骤、目的与观察、调整、出处；从具体日程进入时可记录本次反馈 |

| 家庭会员 | `/family/plan` | S2 提供试用状态、到期时间、权益、家庭共享用量及已有数据导出；S3 增加付费开通与续费 |

| 平板模式 | `/display` | 大字查看当前与下一项、菜谱、活动和提醒，直接进入日历、记录、换餐及时间调整；与普通视图共用成员登录 |
| 打印预览 | `/print/day`、`/print/recipes` | 带日期、更新时间的当天安排与所选菜谱快照 |
| 分享预览与公开页 | `/share/preview`、`/s/:id` | 授权成员预览可公开内容后生成独立快照；访客仅看公开快照并进入产品介绍，在线分享可撤销 |

账号及设备管理支持修改密码和撤销本人设备会话。奶奶与妈妈均可换餐、调整活动和时间；正式记录按家庭读取权限查看，记录的更正与删除按钮仅向记录本人和家庭管理员提供，服务端执行同样校验。AI 聊天和未确认方案仅本人可见，界面注明“确认后的安排将与家人共享”。

邮箱＋密码为首版确定方案，微信入口留待后续；邮箱验证和邮件重置为必要页面流程。食材、近期偏好、作息模板向妈妈和奶奶开放编辑；宝宝关键资料、禁忌及自动生成设置仅管理员可改，其余成员查看。共同提醒由管理员选定；内容启用范围也仅管理员可修改；日常编辑成员可在已启用内容中调整当天安排。

路由属于实现建议，不代表每个入口都需要独立复杂页面；设置和替换可使用抽屉、弹层或短流程。账号与日常功能属于 S1；试用、权益用量和到期导出属于 S2；订单、会员码和续费属于 S3；公开分享与购买后直接开通属于 S4。后三阶段页面尚未加入现有原型，不列入 S1 完成条件。

邮箱注册的交互方案：邀请/受控初始化→填写邮箱→输入邮件验证码→设置密码与本人显示称呼→完成注册并正常登录→进入对应家庭或初次设置。邮箱验证码和重置链接的形式属于开发规格中的工程建议；首次验证邮箱与邮件重置是已确认需求。已有账号从邀请页转到登录，再确认加入；验证邮箱不提前消费家庭邀请，最终加入时再次检查邀请状态。切换邮箱后必须重新验证，不沿用前一个邮箱的凭证。

固定平板使用实际使用者的独立账号，首次登录选择保持登录，后续直接进入。重置密码成功后，全部旧会话失效并显示重新登录入口。收不到邮件时提供检查地址、垃圾箱和重发提示；发信受理不显示成“已送达”。

## 3. 初次设置

建议按以下顺序完成，既提供必要信息，也尽早让家人看到当天安排：

1. 创建家庭，填写宝宝称呼与月龄依据，选择天气城市和时区。精确生日可选；仅提供月龄时同时保存月龄与确认日期，不补造生日。
2. 确认影响菜单的食物禁忌、偏好及信息是否完整。状态不清楚时保留待确认。
3. 使用访谈中的工作日、周末模板作为本家庭的预填建议，调整具体时间。其他家庭使用自己的模板。
4. 查看基础内容的来源和适用说明，启用允许自动安排的内容范围。
5. 进入今日页；随后可邀请家人、在平板登录、确认现有食材。

初次设置的分步与字段数量需要原型实测。缺少食材信息时提示确认；关键食物禁忌未确认时，食谱先以候选状态呈现。

中断后继续已保存的设置进度；重复保存不创建第二份家庭或宝宝。已确认的 11 条旧菜谱在内容整理入口展示为草稿及缺项，导入状态与当前食物限制确认状态分开。实际月龄依据、内容或限制未准备好时，可先看模板，不将草稿显示成已核对推荐。家人加入已有家庭时不重新初始化或覆盖家庭资料。

S1 首位管理员通过受控初始化创建自己的家庭，其他成员通过家庭邀请加入。S2 的受邀家庭从介绍与注册入口创建自己的家庭，完成必要设置后再确认兑换试用，按阶段设计从成功开通起算 7 天。通过家庭邀请进入的照护者加入已有家庭并使用其权益，不必再购买或领取一次试用。外部注册准入细节需在 S2 实现前确定；试用和付费会员流程见第 13 节。

## 4. “今天”页面

标题下增加轻量对话入口：“今天或这周，想怎么安排？”附“安排这周”“调整今天”等快捷操作。它打开 AI 助手，下面继续展示当天实际已保存的安排。

建议的信息顺序：

| 优先级 | 内容 | 主要操作 |
| --- | --- | --- |
| 第一层 | 当前计划时段、下一项安排 | 调整时间、切换活动场景 |
| 第二层 | 天气与穿搭、下一餐 | 查看出门检查、换这一餐 |
| 第三层 | 当天时间线、今天的玩法 | 查看具体做法、替换活动、为本次活动“记一下” |
| 第四层 | 本周共同练习、最近改动 | 查看理由、识别家人的更新 |

时间线使用“按计划：午睡”“下一项：下午茶”等文字。计划经过了某个时间点，仍与实际是否完成分开显示。

每次成功修改后清楚反馈改了哪一项。服务端尚未确认写入时显示“待保存”；已经保存但设备尚未同步时显示各自同步状态，避免让人误以为需要重复保存或其他设备已经更新。

## 5. 辅食调整流程

### 5.1 排餐前确认食材

饮食页 → 家里食材 → 勾选现有与优先消耗 → 可选粗略余量 → 确认 → 查看菜单及待购买食材。

保留上次填写结果和确认时间，方便快速修正。“有安排使用”与“已经用完”分开处理；菜单变动后食材仍由家庭确认。

### 5.2 临时把晚餐的面换成饭

今天或饮食页 → 晚餐“换一下” → 选择替代方案或给出偏好 → 查看该餐变化 → 保存 → 手机和平板同步。

推荐提供一个可选项：“仅这次”或“近期少安排此类食物”。近期偏好的持续时间应可复核，避免一次调整变成永久排除。

替换流程展示直接影响的菜谱和购物需求。如果父母同时修改同一餐，后提交的一方看到最新内容，并可重新选择。

### 5.3 奶奶查看菜谱

在平板登录 → 点下一餐或晚餐的菜谱 → 在本机查看大字原料和编号步骤；也可核对食材、打印或返回平板主页。有编辑权限时可直接换这一餐。

打印预览允许选择当天菜单、单道菜谱或多道菜谱。建议以 A4 和黑白打印可读为起点，长步骤避免被分页截断，所有纸张标注日期与更新时间。

## 6. 活动使用流程

日常安排给出适合当天场景的玩法。户外出门前，平板主页提供一两个容易记住的动作提示；需要更多说明时，直接在平板点“查看玩法”；活动结束后点“记这次活动”，在本机填写文字与反馈记录。

活动卡建议采用两层内容：

- 快速层：一句玩法、所需材料、少量步骤、室内或户外场景。
- 展开层：目的、可观察的反应、如何简化或变化、适用条件和来源。

活动结束后点“记一下”，可以选“喜欢、没兴趣、太难”、补感想或参与情况。记录关联到某天的该次活动；纯内容库详情未指定日期时，记录前选择发生日期或关联安排。记录完全可选，页面避免催促每日打卡。切换场景或替换活动时，仅修改选定安排，并保留已有记录及其原关联。

活动卡以图文为主，说明配图保留；英语示范音频仅在确认核心需要后补充，视频后置。家庭照片上传与内容配图属于不同范围，前者已移除。

## 7. 平板模式结构

平板是可直接登录和操作的完整客户端。平板模式保留清楚的大字摘要，常用操作提供触屏按钮；从详情、日历或记录页可直接返回平板主页。横竖屏均需验证，实际字号和观看距离仍需真机确认。

| 区域 | 内容与操作 |
| --- | --- |
| 顶部 | 日期、家庭、更新时间、家庭入口与普通视图切换；登录过期在本机重新登录 |
| 常用操作 | 日历、饮食、食材、活动、AI助手、记一下 |
| 主区域 | 当前计划时段、下一项、照护者，直接调整时间、打开菜谱和换餐 |
| 辅助区域 | 陪玩、晚餐和穿搭，提供查看玩法、记录本次、换晚餐等操作 |
| 固定提醒区 | 一两条已启用的“本周共同练习” |

主信息保持稳定位置，详情按需要进入。家人能够快速读完一段内容；信息超过屏幕容量时采用摘要与详情，避免全部挤入首屏。

屏幕常亮能力需要浏览器支持、HTTPS 和真机验证。设计上提供进入平板模式、恢复连接和切回普通视图的操作入口；具体操作权限按登录成员决定。可视性和省电行为的技术条件见技术方案。

## 8. 状态与例外

| 状态 | 家人看到的内容 | 下一步 |
| --- | --- | --- |
| 今日尚未生成 | 当天作息骨架，具体内容标记待补充 | 重试生成或选择已有条目 |
| 食材需要确认 | 保留上次信息并显示日期 | 勾选更新或按已知条件手动安排 |
| 天气暂未更新 | 最后成功数据及时间，或明确暂无数据 | 继续查看安排，等待刷新 |
| 临时断网 | 已打开内容、离线提示和最后同步时间 | 恢复联网后取得最新内容 |
| 内容被另一位家人修改 | 最新安排与修改者提示 | 基于新内容继续编辑 |
| AI 暂时不可用 | 已有计划、已核对的候选内容 | 手动选用或稍后重试 |
| AI 方案待确认 | 明确的日期范围、改动清单和“待确认”状态 | 继续对话调整或一次确认保存 |
| AI 方案涉及的内容已变化 | 最新内容、修改者和受影响的改动 | 重新核对后确认，保留当前讨论 |
| 方案保存后暂未同步到设备 | 服务端保存结果与设备最后同步时间 | 设备恢复后读取最新版本，避免重复提交方案 |
| 日期没有记录 | “暂无记录”，并可查看当时计划 | 按需补记，不推断活动未完成 |
| 平板登录失效 | 本机重新登录入口，不继续显示家庭内容 | 在这台平板登录成员账号后恢复使用 |
| 打印后安排变化 | 手机和平板显示最新版本 | 按需重新打印，纸张通过日期与时间区分 |
| 码无效、已用、过期或已撤销 | 对应状态及处理入口，不展示其他购买者或家庭信息 | 核对码的用途，重试查询原兑换结果或联系支持 |
| 试用或会员到期 | 已有计划、记录及查看导出入口；说明停止的新增付费能力和保存期限 | 按需续费或导出，不要求先付费才能取回已有数据 |
| 家庭共享额度用尽 | 当前用量、额度及恢复规则 | 已有内容仍可查看；按已确定规则等待或调整，不静默扣费 |
| 家庭邀请失效 | 过期或已撤销提示，不展示家庭私有数据 | 请有管理权限的家人重新发起邀请 |
| 草稿未核对、内容停用或当前不适用 | 待补齐字段／不可用原因，未来已排条目的处理提示 | 管理员核对内容，日常成员改选已启用且适用的条目 |
| 自动安排没有合适候选 | 作息骨架及明确的待安排原因 | 查看已核对候选或稍后处理，不伪造完整结果 |
| 提交后未收到结果 | 显示正在查询该次保存结果 | 确认结果后显示成功或允许重试，不重复新增 |
| 记录被删除 | 普通列表不显示正文；有恢复权限者可进入回收站 | 查看截止时刻并恢复；其他成员不提供读取入口 |
| 恢复时计划已有新内容 | 当前安排和拟恢复位置 | 核对合并结果后恢复，不覆盖新安排 |
| 已超过 30 天恢复期限 | 已到期、不可恢复的状态 | 不提供恢复操作，清理后不通过历史入口返回正文 |

断网期间保留当前会话已加载内容和输入；重连后先校验身份、读取最新版本，再让成员核对未提交修改。退出或切换账号时清除旧身份的私有显示，不把未提交输入自动带入新家庭；首版不提供关闭浏览器后的完整离线使用承诺。

## 9. 原型评审任务

现有原型已覆盖确认食材并换一餐、切换室内活动、大字菜谱和本机标签页联动；扩展原型已覆盖 AI 讨论与最终方案、月／周日历、按次文字与反馈记录、补记、历史回看，以及方案冲突等演示状态；其中历史照片上传与失败流程已退出当前需求。平板直接操作也已提供本机演示，详见[原型交付说明](../web-ui/README.md)。

下一步补齐邮箱注册、验证与找回、家庭初始化与邀请、来源详情、回收站及最新权限呈现，再接入真实服务。回收站目前只有需求，无运行原型；现有原型测试不证明服务端权限、AI 或跨设备同步已实现。

真机和家庭试用继续评审文字是否看得懂、操作是否太多、屏幕是否看得清。视觉方案沿用 A「日常工作台」，不因文档对齐重新选择设计方向。

## 10. AI 总入口与方案确认

推荐流程：打开助手 → 明确日期范围 → 讨论需求 → 查看方案和改动清单 → 继续调整 → 一次确认 → 查看保存结果和相关页面。

| 内容 | 展示规则 |
| --- | --- |
| 上下文 | 显示当前宝宝、日期范围和关联餐次或活动；从日历进入时带入选中日。已有会话跨页继续，范围切换显式提示 |
| 讨论区 | 保留历史消息和当前讨论；查询直接回复，需要补信息时围绕影响方案的内容提问 |
| 方案区 | 按日期展示安排；一周方案提供按天摘要，标出已有内容和拟改内容 |
| 改动清单 | 分组显示日程、菜单、食材和偏好等改动，注明生效日期、期限及直接影响 |
| 确认操作 | “确认并保存”对应当前最终版本；用户继续修改后，旧预览标为已替换，避免执行过期方案 |
| 保存结果 | 服务端成功后才显示“已保存”，提供“查看日历”“查看菜单”等入口；失败时保留方案便于重试 |

示例需求：“这周户外为主，家里胡萝卜先吃，晚饭先少排面。”AI 先整理活动、餐次、食材优先级和偏好期限，用户可以继续说“周三不动”“只调整晚餐”。明确的修改范围进入最终预览，未确认的描述不自动更新家庭资料。

一次确认覆盖所显示的整组业务改动。界面按钮、确认状态和执行结果由应用提供，聊天文本本身不作为已经保存的证明。聊天与未确认方案仅发起人可见；共享日程只显示保存成功的正式结果。

## 11. 日历与记录流程

月历负责选日期和概览，标记“有安排”“有记录”，不以颜色单独表达状态。电脑可以并排放月历和选中日时间线，手机采用紧凑月历加下方列表；整周安排可按天切换查看。

选中日显示两类相互关联的信息：计划条目，以及家人实际保存的记录。过去日期优先展开实际记录，并保留查看当时计划的入口；未来没有实际记录时只显示已保存安排。

“记一下”表单的建议字段：

| 字段 | 规则 |
| --- | --- |
| 发生日期、时段 | 从所选日程或日历带入，可修改；具体时刻选填，也可只选上午或下午 |
| 关联安排 | 从活动卡进入时预填；临时发生的事情可独立记录 |
| 参与情况 | 可选“参与了”“玩了一会儿”“未开展”等，默认未填写 |
| 宝宝反应 | 可选兴趣反馈和自由文字；与参与情况分开 |
| 家长感想 | 可写一句或多句，保留原文 |
| 记录人、填写时间 | 按当前账号和保存时间自动记录，与活动发生时间分别展示 |

参与情况、兴趣反馈、感想至少填写一项即可保存；感想不自动标记完成。表单不提供家庭照片或附件入口，保存失败保留输入，重试不得重复创建记录。

实际发生日期不得晚于家庭当前日期；选择未来日期时引导改为计划或修正发生日期，保留其他已填内容。只写感想也可保存，缺失的参与和兴趣继续保持未知。

记录详情保留本次活动的日期、原安排、家长原话与反馈。补记、编辑和删除按成员权限执行；修改日程不会删除已存在的记录。示例“下午寻找秋天的颜色”仅用于验证流程，示例中的宝宝表现不能写成用户家庭已发生的事实。

### 11.1 回收站与恢复

家庭页和日历提供回收站入口；计划条目与文字记录分组。计划按日常编辑权限恢复，文字记录仅原作者或管理员可见并恢复；页面和服务端都检查当前成员资格。列表展示原日期、类型、原作者、删除人／时间和准确恢复截止时刻。

删除前说明“移入回收站，30 天内可恢复”，成功后从正常列表移除；取消安排使用单独操作，继续保留可回看的取消状态。恢复记录保留原作者、发生日期及当时快照；恢复计划先核对当前日计划，出现变化时预览恢复位置与合并结果。响应丢失时查询同一次操作，不能生成第二份记录。

到期后不提供恢复操作，正文随清理流程移除；不把备份仍可能包含副本描述成可随时恢复。用户自行打印的纸张不受在线删除控制。容量问题单独提示，不按记录年龄静默清理；自家规则不自动作为 S2／S3 的会员政策展示。

## 12. 推荐理由与来源详情

展示内容遵循已确认的[内容来源与推荐规则](内容来源与推荐规则.md)。页面先给出可执行建议，再简短解释今天选择它的原因，展开后可以核对原文、具体做法来源、改编及实际用到的家庭记录或天气数据。具体入口布局属于待验证交互设计。

| 位置 | 信息要求 |
| --- | --- |
| 饮食与菜谱 | 区分一般营养原则、家庭或其他做法来源、实际影响选择的库存与近期偏好；未核对的份量和条件保持待补充 |
| 活动卡 | 显示目的、观察和调整；来源定位到具体玩法或段落，标明原文整理或本地改编 |
| 天气与穿搭 | 显示城市或地点、当前或预报类型、活动时段、来源与最近取数时间；穿搭解释天气和活动方式的影响 |
| 来源详情 | 展示标题、作者或机构、链接、版本或日期、具体章节或段落、适用条件，以及真实核对或审核状态 |
| 平板与打印 | 保留简短理由和必要的数据时间或来源标记；详细依据在获授权的管理页查看，打印保留内容版本与日期 |

家庭认可、出处核对和专业审核分别表达；原型示例不显示成家庭真实反馈或正式天气数据。本次仅补充文档要求，尚未将来源详情接入页面。

## 13. 家庭会员与对外分享

已确认方向和待验证项见[分享与家庭会员方案](分享与家庭会员方案.md)。沿用 A「日常工作台」的视觉与导航，不给日常照护页面增加独立的会员主导航；具体布局待对应阶段实现和评审。

- 新家庭：示例与介绍 → 注册 → 创建家庭并设置 → 核对 7 天试用权益并兑换 → 进入今日计划。
- 家人加入：家庭管理中的「邀请家人」 → 登录 → 确认家庭及角色 → 加入并共用家庭权益；不进入购买流程。
- 会员开通：家庭会员页 → 核对套餐、价格、额度及政策 → 购买并取得激活码 → 选择家庭 → 预览生效及到期时间 → 确认兑换 → 查看服务器返回的开通结果。
- 对外分享：选示例或可分享的计划 → 预览公开快照 → 主动分享 → 其他家庭从产品介绍创建自己的空间；家庭邀请链接不放入公开内容。

会员页同时展示家庭名称、试用或会员状态、服务截止时间和家庭合计用量。29 元／家庭／30 天仅作为文档中的测试报价，正式展示价格需经成本与测试验证；不得把未实现的服务标为可购买。具体支付与退款信息在渠道确定后补齐。

兑换前显示「为哪个家庭开通」「包含什么」「开通后何时到期」，同一个码只能成功兑换一次。提前续费保留原有剩余天数；已开通但页面响应失败时提供查询结果入口，避免重复购买。非授权成员能查看状态，但管理与开通操作按对应权限提供。

到期提示使用明确日期和功能说明，保留已有安排、记录在告知保存期限内的查看与导出；不以遮挡历史记录催促续费。保存期限和导出方式在开放外部试用前确定，页面不默认承诺永久留存。

公开分享预览默认排除宝宝姓名、地点和家庭内部链接，展示最终将公开的内容。在线分享页只能读取该快照，并支持撤销；外部用户不能借由分享页进入家庭日历或记录详情。当前原型没有公开分享服务。

后续评审补充：新家庭试用、家人免费加入、兑换前核对家庭、已用码与网络重试、续费到期时间、到期后导出，以及公开分享的预览与撤销。
